# Figma Network Probe

Экспериментальный сборщик, не декодер дерева. Рабочее расширение в `extension/` не меняется.

1. В Chrome открой `chrome://extensions`, включи режим разработчика.
2. Нажми «Загрузить распакованное расширение» и выбери эту папку.
3. Открой ссылку на selection в Figma. Дождись загрузки. Закрой DevTools для этого прогона.
4. В меню расширений открой **Figma Network Probe** → «Начать запись и перезагрузить Figma».
5. После загрузки подожди 10–15 секунд. Раскрой несколько слоёв, выбери два разных слоя, затем исходный фрейм.
6. Открой расширение → «Остановить запись» → «Скачать дамп JSON».

Разрешение `debugger` нужно для CDP Network и подключения к worker-процессам. Chrome покажет уведомление об отладке. Сборщик не меняет макет, но перезагружает вкладку. Cookies, HTTP-заголовки, тела исходящих HTTP-запросов и query-параметры URL не записываются. Сами HTTP/WS payload могут содержать приватные данные и сведения сессии: дамп предназначен для локального анализа, не для публикации или коммита.

После остановки последний дамп хранится в локальном хранилище расширения и перезаписывается следующим остановленным прогоном. Удаление расширения удаляет это хранилище; скачанные файлы остаются в Downloads. Во время записи данные находятся в памяти, перезапуск браузера может их потерять.

Лимит — 24 MiB записанных событий и 10000 событий; `dropped` означает неполный захват. В 0.2.0 собираются только входящие WebSocket-сообщения `/api/multiplayer/<выбранный файл>` на www.figma.com и метаданные подключения workers. HTTP, livegraph и исходящий обмен исключены. Другие транспорты и поздно подключённые workers могут оставлять пробелы. Отсутствие дерева в дампе не доказывает невозможность подхода. Кнопка удаления очищает локально сохранённый дамп, но не скачанные JSON.

Первый критерий успеха: найти ID выбранного узла, его детей и порядок, сопоставив с Layers. Затем отдельно проверять свойства и обновления. Сначала анализировать метаданные, размеры и сигнатуры; не печатать целиком приватные payload.

## Результат первого реального прогона, 25 октября 2026

Перехвачен `fig-wire` v1: после 12-байтового заголовка идёт Zstandard-сжатая бинарная схема Kiwi (666 определений). Последующие бинарные сообщения этого сокета также сжаты Zstandard. Схема успешно прочитана `kiwi-schema@0.5.0`. Начальное `NODE_CHANGES` содержит 45440 уникальных записей с фазой CREATED; также получен JOIN_END.

По выбранному ID восстановлена ветка из 118 записей через `parentIndex.guid`. Имя корня Banner Content и размер 1904×392 совпали с видимой панелью Figma. Есть тексты, шрифты, заливки и Auto Layout. Это дерево явных родительских связей: раскрытие INSTANCE, наследование, overrides, порядок всех соседей, геометрия из blobs и живые обновления ещё не проверены. Полнота дерева относительно интерфейса не доказана.

Дамп достиг лимита 24 MiB, 110 событий пропущены. Существенную часть лимита заняли шрифты и другие HTTP-ресурсы. Следующий сборщик стоит ограничить multiplayer-сокетом и отдельно нужными HTTP-ответами. Приватные дампы и декодированные данные хранятся в Downloads и игнорируемой `.local/`, не в исходниках.

Воспроизводимый локальный декодер (нужен `zstd`):

```sh
npm install --prefix .local/network-analysis --ignore-scripts kiwi-schema@0.5.0
NODE_PATH="$PWD/.local/network-analysis/node_modules" node experiments/figma-network-probe/decode.cjs /absolute/path/figma-probe.json 1:22975 .local/network-analysis/selection
```

Декодер принимает ровно один начальный пакет CREATED и явно отклоняет неподдерживаемые варианты. Выдаёт `tree.json`, `nodes.json` (без editInfo) и `report.json`; не печатает payload или сведения сессии.

## Повторный прогон 0.2.0 и MCP

Расширение обновлено в реальном Chrome. Повторная загрузка того же файла дала 22 события, 13 входящих сообщений, около 4.46 MiB и **0 пропусков**. Новый `get_network_tree` прочитал 45440 записей и вернул выбранные 118 узлов через настоящий stdio MCP. Проверены имя и размер корня; полная визуальная эквивалентность дерева остаётся открытым вопросом.

Новый декодер находится в `src/network.ts`, worker — в `src/network-worker.ts`. Он поддерживает несколько начальных пакетов CREATED до JOIN_END, ограниченную выборку с пагинацией и скрытые ветки. Поздние изменения явно игнорируются: live-синхронизация ещё не реализована. Старый `decode.cjs` сохранён как исходный диагностический эксперимент.

Один сравнительный замер на новом дампе в отдельных Node-процессах:

| Вариант | Время | JS-куча после GC | Пиковый RSS процесса |
| --- | ---: | ---: | ---: |
| Полное Kiwi-декодирование с удержанием документа/blobs | 1477 мс | 534 MiB | 694 MiB |
| Компактные свойства + индекс дерева | 714 мс | 117 MiB | 339 MiB |

Это разные объёмы сохраняемых данных; замер демонстрирует пользу сокращения модели, а не превосходство языка. Компактный вариант не хранит geometry blobs и не раскрывает компоненты. Настоящий MCP-прогон занял около 1.15 с на загрузку/декодирование/индекс и 3 мс на выборку. Worker завершается после ответа. Память вкладки Figma в эти цифры не входит; реализация Rust не измерялась.
