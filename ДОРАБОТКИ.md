# Потенциальные доработки Rust MCP

Единый список на 26 октября 2026. Это задачи для последующего выбора, а не обещание их реализации в рамках очистки репозитория. Источники: текущий Rust-сервер и расширение, переданный пользователем отчёт корпоративной модели, незавершённые критерии прежних планов. Отчёт относится к Rust, но точная версия установленного сервера и расширения не указана. Наблюдения отчёта не считаются воспроизведёнными здесь.

## 1. Восстановление наблюдения после reconnect — высокий приоритет

Подтверждено кодом: потеря соединения завершает наблюдение; новое подключение не восстанавливает полноту старого снимка. `connected: true` может сочетаться со `STALE` при чтении.

- [ ] Отдельно показывать состояние моста, захвата и готовность чтения в статусе и интерфейсе.
- [ ] Предложить явный повторный захват либо реализовать безопасное автоматическое восстановление. Перезагрузка вкладки должна быть ожидаемой частью выбранного режима.
- [ ] Не возвращать старый снимок как свежий: пропущенные изменения требуют нового полного захвата либо доказанной непрерывности потока.
- [ ] Проверить потерю WebSocket, рестарт service worker и MCP, навигацию, reconnect во время пагинации и live-update. Старые continuation должны отклоняться, новый захват должен восстанавливать чтение.

## 2. Ложная и длительная блокировка экспорта — высокий приоритет

Подтверждено в `extension/connection.js`: `exportUncertain` выставляется до `begin_export`; при `nativeCopyStarted === false` сбрасывается только для `get_screenshot`, а для `export_asset` сохраняется. Общая проверка флага блокирует оба инструмента. Поэтому наблюдение отчёта «скриншот продолжал работать» требует сверки версий и последовательности вызовов.

- [ ] Разрешить повтор экспорта после доказанной ошибки до начала native copy.
- [ ] Разделить стадии подготовки, реально запущенного копирования, ожидания и неопределённого результата.
- [ ] Определить безопасное восстановление после таймаута или отмены. Простого сброса флага недостаточно: поздний результат предыдущего copy может попасть в следующий запрос.
- [ ] Проверить сохранение состояния при рестарте worker, перезагрузке вкладки во время запроса и разрыве моста.
- [ ] Проверить пакетный экспорт: ошибка одного узла, дальнейшие узлы, PNG/SVG и скриншот после ошибки.

Готово, когда ошибки подготовки не блокируют следующие попытки, а неизвестный исход native copy не допускает выдачу чужого результата.

## 3. Доступность узла для экспорта — средний приоритет

Сетевой снимок может содержать узел, отсутствующий в смонтированных Layers. Отчёт связывает это с расположением панели далеко за пределами видимой области; точная причина не воспроизведена.

- [ ] Сверить путь поиска узла в `extension/dom.js` и fallback-навигацию в `extension/connection.js` для экспорта и скриншота.
- [ ] Реализовать ограниченное раскрытие предков/подгрузку узла, если это возможно без повреждения наблюдения.
- [ ] Явно сообщать, когда необходима смена страницы или новый захват.
- [ ] Проверить удалённый от viewport узел, свёрнутых предков, другую страницу и instance; выполнить context → PNG/SVG → context.

## 4. Причины разрывов и гонки capture/read — высокий приоритет

Rust `standalone.rs` использует `1008` для разных отказов. В ряде ветвей отправляется close с причиной, но локальная переменная `reason` остаётся пустой; итоговый `lastDisconnect` теряет диагностику. При новом подключении история сбрасывается. Гипотеза отчёта о вытеснении старого подключения второй вкладкой не соответствует текущему коду: новый peer отклоняется, пока старый активен.

- [ ] Сохранять локальную причину во всех ветвях закрытия, включая capture failure и переполнение/занятость очереди; различать инициатора закрытия.
- [ ] Различать штатную остановку MCP и policy rejection. При переносе теста обнаружено: штатное закрытие Rust-сервера приводит к состоянию ошибки расширения вместо автоматического reconnect; аварийный обрыв нужно проверять отдельно.
- [ ] Не терять последнюю диагностическую запись сразу после reconnect; добавить ограниченную историю без секретов и содержимого макета.
- [ ] Проверить overlap live delta / cold-read / пагинации / heartbeat. В Rust есть ветвь `Capture busy or file mismatch` при занятости чтения; выяснить, приводит ли она к наблюдаемому спонтанному `1008`.
- [ ] Воспроизвести обрыв под той же нагрузкой и с теми же версиями. Успешный большой обход не исключает гонку и не доказывает внешний источник разрыва.

## 5. Файл результата вместо обязательной пагинации — решение по контракту

Сохранена прежняя идея: один вызов потоково записывает полный результат в JSON, возвращая путь, сводку, число узлов и признаки неполноты; небольшой ответ можно отдавать целиком. Пагинация остаётся возможным режимом для клиентов без доступа к файлу.

- [ ] Выбрать режим API и проверить доступность файлов локальному/удалённому агенту.
- [ ] Определить границы памяти и размера, срок хранения, отмену, атомарную публикацию и очистку.
- [ ] Сохранить ограничения глубины, unresolved-диагностику и гарантии revision: файл сам по себе не делает чтение полным или свежим.

## 6. Сквозная приёмка автономного Rust — средний приоритет

Исторические замеры Node и гибридного сервера не являются приёмкой текущего Rust. Миграционные сравнения удалены; история доступна в Git для ранее отслеживаемых файлов.

- [ ] Проверить чистую установку и реальный Figma/Kilo-сценарий на macOS и Windows, отдельно Linux при заявлении полноценной поддержки.
- [ ] Полный обход всех страниц, повтор, смена selection, live-изменения, PNG/SVG, отмена, shutdown и восстановление без потерянных процессов и scratch.
- [ ] Измерить cold/warm latency, CPU, RSS, диск, простой и 100 смен selection на малом/большом файле. Бюджет 500000000 байт проверять как одновременный общий пик сервера и добавочной памяти расширения, а не сумму разновременных пиков.
- [ ] Проверить Windows-пути, блокировки файлов, очистку, остановку процесса и воспроизводимость release-сборки.
- [ ] Разделять ошибки провайдера модели/HTTP 429 и задержки агента от скорости MCP. Полноту пагинации проверять по фактическим tool events (`scripts/check-kilo-pages.mjs`).

## 7. Сопровождение и поставка — низкий приоритет

- [ ] Рассмотреть готовые release-пакеты и установку без локальной сборки; обеспечить проверку целостности и обновление расширения вместе с сервером.
- [ ] Расширять независимые Rust-регрессии для fault/cancellation/storage и значимых свойств макета; сохранённый эталон обхода не покрывает все старые differential-тесты.
- [ ] При отдельном рефакторинге переименовать внутренние `stage6/7/8` по назначению и убрать ненужные диагностические CLI-режимы после аудита их использования.

## 8. Адресный и компактный контекст — идеи из прежних БТ

Старые предложения по сетевому источнику уже реализованы частично; приведённые ниже возможности требуют отдельного сопоставления с текущим Rust-контрактом, а не повторной миграции.

- [ ] Рассмотреть обзор структуры и компактную проекцию с выбором групп полей (layout, текст, стили, ассеты, диагностика), batch-чтение конкретных узлов и адресное объяснение происхождения свойства/подбора переменной.
- [ ] Поиск по имени, типу и тексту в ограниченной области с явным покрытием: отсутствие совпадений в части дерева не означает отсутствие в документе.
- [ ] Сводки повторяющихся стилей/структур со ссылками на узлы и сохранением исключений; не терять индивидуальные тексты и не приравнивать визуальное сходство к компонентной связи.
- [ ] Проверить бюджет окончательного ответа вместе с предупреждениями и continuation. Для одного чрезмерно большого узла рассмотреть чтение полей или частей текста вместо потери данных.
- [ ] Рассмотреть публичную выдачу разницы между revision/снимками и проверить восстановление результата применением этой разницы.
- [ ] Измерить вклад описаний инструментов и повторной диагностики в контекст модели; возвращать краткие сводки и детали по запросу.
- [ ] Подготовить переносимый Rust-бенчмарк одной командой: синтетические деревья на 100/1000/10000 узлов, глубокие/широкие ветки, повторяющиеся карточки с исключениями, поиск, пагинация, повторные запросы и живые изменения. Без приватных файлов, платной модели, аккаунта и сети во время основного прогона; живой браузер — отдельный режим.

Критерий оптимизации — сохранение необходимых фактов и явной неполноты при меньшем объёме и числе повторных чтений. Постоянный индекс ограничивать выбранной веткой и необходимыми зависимостями; не накапливать полные документы и прежние selection в RAM. Очистка управляемого кэша не должна затрагивать ключи, конфигурацию и экспортированные ассеты.
