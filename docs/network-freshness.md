# Актуальность снимка и восстановление (TODO 15)

**Первые живые сбои исправлены; статус полной приёмки TODO 15–16 остаётся открытым.** [Наблюдавшиеся сбои и незакрытые критерии](network-live-ui-check.md).

После JOIN_END/finish расширение сохраняет debugger, список наблюдаемых сокетов и дочерних сессий. Полный документ и история изменений в RAM не накапливаются. Неподдержанный multiplayer-фрейм, кроме opcode 9/10, консервативно делает снимок устаревшим. Известный служебный трафик классифицируется до требования индекса. TODO 16 добавляет [ограниченное применение входящих изменений](network-live.md) при готовом свободном индексе. Разрешённое подмножество сообщений присутствия и исходящего служебного обмена описано в network-live.md. Исходящие post-JOIN пакеты передаются локальному MCP для классификации, но не записываются в snapshot.

Переполнение ограниченной очереди, новый multiplayer-сокет, отключение его worker, debugger или моста также прекращают наблюдение. При перезагрузке готового документа, смене файла/вкладки и явной остановке прежнее наблюдение прекращается. Остановка закрывает мост разрешённым для браузера кодом 4008 и снимает debugger; popup показывает `stale` и причину. Ошибка до установления границы начального снимка остаётся `error`. Пассивное наблюдение в ready не блокирует существующие UI-запросы; их исходящий трафик может инвалидировать снимок.

Сервер связывает единственное наблюдение с fileKey/sessionId/generation и владельцем аутентифицированного соединения. После finish отправитель сохраняет обработчики и посылает heartbeat через 5 секунд после подтверждения; сервер требует следующий heartbeat не позднее 15 секунд. Это служебный обмен без чтения документа. Отключение, протокольная ошибка или таймаут отменяют наблюдение. Дополнительная проверка монотонного срока при чтении и heartbeat не позволяет просроченному наблюдению ожить из-за задержки выполнения таймера. После reconnect нужен новый захват, прежнее поколение не восстанавливается автоматически.

`ready.json` означает сохранённые и проверенные байты. Новый флаг `monitored: true` требует живого наблюдения для выдачи контекста. Наблюдение не хранится на диске: после перезапуска MCP такой снимок возвращает `STALE`, даже если ready.json сохранился. Старые снимки без флага и ручные captureFile доступны для исследования только с явным `freshness.status: historical`: актуальность документа не подтверждается. Для живого наблюдения возвращается `freshness.status: observed`, идентификатор снимка и локальная revision принятых изменений документа. Это отсутствие необработанных наблюдавшихся изменений, а не серверная ревизия Figma.

Reader проверяет наблюдение до декодирования, после worker и перед возвратом ответа. Его сигнал отменяет активное чтение; idle-индекс освобождается, устаревший результат и continuation не выдаются. Смена поколения или применённое изменение документа меняет привязку pagination и исключает использование старого индекса. Низкоуровневые readManifest/readPart остаются доступными для проверки сохранённых байтов и сами по себе не доказывают актуальность.

## Восстановление

1. Если наблюдение ещё активно, нажать «Остановить захват».
2. Нажать «Подключить» для выбранной вкладки Figma.
3. Нажать «Перезагрузить и захватить». Перезагрузка явная; создаётся новая случайная sessionId.
4. Дождаться ready. Продолжения прежнего снимка использовать нельзя.

Скрытого UI-fallback нет. Основной get_design_context переключается в TODO 18.

## Проверки и границы

Автотесты проверяют изменения в обоих направлениях, ping/pong, замену сокета, отключение worker/debugger/моста, остановку, очередь после JOIN_END, гонку finish, heartbeat, просроченное наблюдение, отсутствие живого владельца, stale continuation, отмену worker и восстановление новым поколением. Интеграция использует настоящий WebSocket, disk store и worker, но моделирует Chrome Debugger. Измерительный replay сохраняет наблюдение до завершения чтений и замеров простоя.

CDP не даёт сквозного номера сообщений сервера Figma. Последовательности частей/записей выявляют пропуски в нашем транспорте; разрывы и отсутствие heartbeat приводят к консервативному устареванию. Невидимую потерю события внутри самого браузера невозможно доказательно исключить этим интерфейсом. `observed` не обещает синхронную серверную ревизию или отсутствие задержки доставки событий. Результаты живого чтения Chrome/Figma записаны в network-live-ui-check.md. Реальные изменения документа, Windows и полный RAM-бюджет остаются отдельной приёмкой.
