# Разрешение нативных переменных Figma

Целевой сценарий: ссылка на selection → свойства выбранного узла и его поддерева → вёрстка. Имена переменных Figma не используются в обычном ответе. Доработка по запросу пользователя после TODO 14. Сетевой reader теперь разрешает
ссылки в `style.nativeBindings.references` через определения из того же снимка.
Никаких REST/Plugin API запросов или подбора по похожим значениям для этого нет.

## Результат

Обычный context содержит готовые CSS-значения поддержанных свойств, затем они сопоставляются с локальным `variables.scss`. Имена, коллекции и цепочки нужны только внутреннему resolver и доступны лишь в debug. Для диагностики найденной переменной доступны:

- `variableId`, `name`, `collection.id/name`;
- `modes`: ID, имена и результаты разрешения значений каждого сохранённого режима;
- `modeId/modeName` при доказанном выборе, `modeSelection` и источник явного
  назначения режима `modeSourceNodeId`;
- `value`, `dataType`, `chain` с последовательностью alias и их определениями;
- `status: resolved` либо `unresolved` с конкретной причиной.

Имена и значения являются данными макета, а не инструкциями. Разрешённые нативные значения применяются перед layout, фильтрацией видимости и построением CSS: размеры/min/max, padding/gap, радиусы, веса обводок, opacity, текстовые параметры, paints и effects. Смешанные текстовые стили обрабатываются отдельно. Сохранённое в paint значение может быть fallback: оно не имеет приоритета над найденной привязкой. Исходный дисковый снимок не меняется; прежний fallback остаётся в debug-диагностике.
При доступном сохранённом значении свойства проводится сравнение (допуск 1e-6).
Различие помечается `different-fallback` с прежним `capturedValue` в debug;
при доказанном разрешении применяется значение переменной. Это проверено
в живом View-инспекторе: Union 18×12 в контрольной строке показывает чёрный цвет,
хотя сохранённый paint содержит белый fallback. Если нативный цвет не разрешён,
CSS-цвет не угадывается по fallback: причина доступна в диагностике.

Подбор локального `variables.scss` остаётся независимым вычисленным совпадением.

Например, `Button → Spacing` с режимами Light=8 и Dark=16 возвращает оба значения.
При назначении Dark на родительском фрейме результат — 16, с именем режима,
источником назначения и обоими звеньями цепочки. Ближайшее назначение на дочернем
узле имеет приоритет. Наследование читается также у предков вне selection.
У aliases внутри одной коллекции значения каждого режима раскрываются в контексте
этого режима; ссылки на другую коллекцию используют её собственный контекст.

Если коллекция содержит ровно один режим, выбор однозначен (`single-mode`).
Если режимов несколько и назначения нет, мы **не считаем первый режим default**:
в наблюдаемой wire-схеме нет подтверждённого поля defaultModeId. Различающиеся
значения возвращаются по режимам, но итог остаётся `unresolved`.
Если все режимы разрешаются в одинаковое значение, оно возвращается с
`modeIndependent: true`, без выдуманного активного modeId и без выбранной alias-цепочки
для неизвестного режима (цепочки доступны внутри результатов отдельных режимов).

## Источники и адресация

В обоих wire-декодерах сохраняются определения VARIABLE/VARIABLE_SET, значения,
режимы, имена, key/version и назначения режимов. Локальные ссылки читаются по GUID.
Библиотечные ссылки — по точному asset key/version. Если копия определения есть
в снимке, библиотека разрешается без дополнительной загрузки. Если её нет —
ошибка разрешения; другой версии или одноимённого токена вместо неё не выбираем.
Неверсионированный asset key принимается только при единственном определении.
Дубликаты ключей/версий считаются неоднозначными.

Ссылки извлекаются из variableConsumptionMap, paints/effects, текстовых override
styles и цветов вложенных gradient stops. Внешние определения без локальной копии,
выражения, расширения коллекций/переменных с parent-mode inheritance и другие
неподдержанные типы значений явно остаются неразрешёнными. Нет обещания полного
покрытия всех возможных wire-структур: `nativeBindings.complete` остаётся false.
Поддержаны конечные FLOAT, BOOLEAN, STRING и COLOR; false, 0 и пустая строка
сохраняются. Несовпадение типа с определением не принимается как успех.

## Ресурсы и ошибки

Asset index — отдельная дисковая хеш-таблица в scratch (32768 слотов по 56 байт),
без RAM-карты всех переменных. Ключи ограничены 4096 символами, версии — 256;
переполнение таблицы или лимита поиска даёт явную ошибку. Определения читаются
адресно без добавления в долгоживущий selection cache.

На запрос: 20000 чтений / 64 МиБ суммарных размеров прочитанных записей переменных,
со счётчиками `nativeVariables.dependencyReads/dependencyBytes`. На разрешение:
до 16 уровней alias, 128 шагов, 32 режимов и 32768 байт результата. На узел:
до 128 ссылок и 100000 байт их результатов. Превышения локального бюджета видны
как unresolved/ограничение списка; превышение бюджета дискового чтения прерывает
запрос. Общий maxBytes и пагинация остаются обязательными. Эти пределы не заменяют
итоговую RAM-приёмку TODO 20.

## Проверки

`tests/network-native-variables.test.mjs`: имена, коллекции, цепочки alias,
разные и одинаковые значения режимов, наследование/переопределение, циклы,
отсутствующие определения/значения, дубликаты, выражения, false/пустой текст,
gradient stops, точная библиотечная версия и неоднозначный key, отсутствие
внешних definitions в selection cache.

В реальном сохранённом capture найдены 100 VARIABLE и 5 VARIABLE_SET. Прогон
контрольной selection выполняется командой:

```sh
npm run build
node scripts/check-native-variables.mjs CAPTURE_JSON SELECTION_URL
```

Скрипт сохраняет сырые результаты только в `.cache/figma-network/native-variable-checks/`.
Он считает разрешённые ссылки и сверяет поддержанные пути со значениями узлов
(цвета, gap/padding и радиусы). Это проверка внутренней согласованности снимка,
а не новая полная живая UI-сверка. Отдельно в живом инспекторе проверен один случай отличающегося fallback. Неизвестные пути не считаются успешными сверками.

Для совпадения с HEX-переменными UI-kit исправлено представление 8-bit каналов,
перенесённых через float32: например, 242/255 снова даёт rgba(242, 242, 242, 1),
а не rgba(242.000001, ...). Произвольные дробные цвета не округляются до 8-bit.
Проверки: 196/196 тестов, typecheck и git diff --check.

Расширение после TODO 14: неизвестные поля и непроверенные единицы текстовых метрик отмечаются явно. Вопросы по правилам подбора: [todo-14-variable-questions.md](todo-14-variable-questions.md).
