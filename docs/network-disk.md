# Ограниченное дисковое декодирование (TODO 08)

25 октября 2026. Реализовано без новых зависимостей. TODO 09 не начат: каждый запрос пока заново декодирует снимок, постоянного индекса selection нет.

## Путь чтения

`get_network_tree` принимает ровно один источник: `snapshot: {fileKey, sessionId, generation}` управляемого кэша или исследовательский `captureFile`. Для обоих нужен `url` выбранного узла. Основной `get_design_context` переключается отдельным TODO 18.

`readStoredNetworkSnapshot` удерживает read lease в MCP-процессе на всё чтение. Worker последовательно проверяет manifest и SHA-256 частей через `NetworkStore`, собирает не больше одной NDJSON-записи и проверяет последовательность/идентичность потока. Старый probe JSON читается потоково по одному событию; весь файл не превращается в строку/объект.

Одна тяжёлая операция на процесс, в том числе между экземплярами MCP-сервера: конкурентный вызов получает BUSY. Блокировка удерживается до завершения worker и удаления временных файлов. Очередь запросов не создаётся. Отмена и таймаут 120 секунд завершают worker. Ошибки и неполнота не приводят к UI-fallback.

## Замена Kiwi-декодера

Сгенерированный `kiwi-schema` decoder создавал `Array(length)` из недоверенной длины, возвращал весь `nodeChanges` и выделял пропускаемые blobs. В рабочем пути он заменён интерпретатором `BoundedWireDecoder`. Из существующей зависимости используется ограниченный байтовый reader; схема разбирается с лимитами до построения таблиц, динамической генерации кода нет.

Узлы верхнего уровня посещаются отдельно, вложенные overrides не становятся узлами документа. Ненужные поля и blobs пропускаются без построения объектов/массивов содержимого. Тот же декодер проверяет маркеры начального снимка в `InitialSnapshotInspector`. Исследовательский `NetworkSnapshot` оставлен для сравнения и старых тестов; production worker его не использует.

## Дисковые данные и границы

В `.cache/figma-network/decode-*` создаются три файла: лог узлов, хеш-таблица с фиксированными слотами и связный список дочерних ссылок. Все записи ограничены; не создаются сотни тысяч файлов. Узел может прийти раньше родителя. Дубликаты обнаруживаются на диске. Порядок детей определяется wire position. При чтении в RAM находятся один узел, ограниченный список детей одного родителя и сведения обхода только выбранной ветки. Ответ по-прежнему раскрывает ограничения instances/rendered tree.

| Ограничение | Значение / поведение |
|---|---|
| Схема | 2 МиБ, 2000 определений, 20000 полей, имена до 256 байт |
| Распакованное сообщение и окно Zstandard | 64 МиБ; неизвестный размер, словари, склейка и повреждённые блоки отклоняются; фактический выход считается отдельно и должен совпасть с заголовком |
| Массивы | 200000 элементов; сохраняемые массивы до 10000; пропускаемые byte blobs до размера сообщения |
| Вложенность / работа | 64 уровня, 32 млн операций на сообщение, 100000 на узел; оценка сохраняемых значений до 2 МиБ до аллокаций |
| Строка / сохранённый узел | до 1 МиБ каждый; превышение даёт ошибку |
| Документ | 200000 узлов; лог до 512 МиБ |
| Хеш-таблица | 24 МиБ на диске; до 400000 занятых слотов с учётом отсутствующих родителей; до 4096 проб на поиск |
| Дети одного родителя | 10000, суммарно до 2 МиБ ключей порядка; иначе явная ошибка с предложением выбрать меньшую ветку |
| Legacy JSON | до 1 ГиБ; 10000 событий, одна запись до 24 МиБ + 4096 байт; метаданные по 64 КиБ, до 32 ключей |
| Диагностические списки | до 1000 ID; полные счётчики и признак сокращения сохраняются |
| Worker heap | 128 МиБ old + 16 МиБ young; это страховка, не замена измерению RSS |

Готовые снимки хранятся как прежде. Временный индекс удаляется в `finally`, включая ошибку декодирования и отмену. При аварийном завершении всего MCP ОС закрывает дескрипторы, но `decode-*` может остаться; автоматическое восстановление после краша и единый lifecycle относятся к TODO 17. Неизвестные каталоги существующая очистка намеренно сохраняет. Индекс selection и его повторное использование — TODO 09, адресные продолжения и полный бюджет ответа — TODO 10.

## Проверки и измерения

`npm run check`, `npm test` — 150/150. Новые проверки покрывают схему/varint, вложенность, чрезмерные массивы/строки, дубли полей, хвостовые байты, пропуск больших blobs, Unicode, split records, child-before-parent, порядок/visibility/depth/offset, циклы, повреждённые части, конкурентные читатели, блокировку очистки, отмену и освобождение scratch. Полный stdio-стенд теперь использует managed snapshot напрямую.

```sh
npm run measure:network:disk
npm run measure:network -- --capture /absolute/path/probe.json --node-id 1:22975 --idle-ms 100 --release-ms 1000
```

Первый стенд создаёт большой снимок потоково вне измеряемого процесса, затем запускает production reader в отдельном процессе. Кэш, конфигурация и сырые отчёты остаются в `.cache/figma-network/benchmarks/`. RSS worker входит в RSS процесса и не суммируется повторно. OS `maxRSS` учитывает краткие пики процесса; внешний опрос — дополнительная проверка. Бюджет этого стенда — 350000000 байт декодера с резервом 150 МБ из общего целевого бюджета для остальных компонентов. Резерв не является измерением расширения.

[Числовой отчёт без содержимого макета](network-disk-measurements.json). macOS 24.6, arm64, Apple M1, Node 20.12.2:

- Большой managed snapshot: **200000 узлов**, 1024 байта имени на узел, **275773546 байт** входных частей. Выбранная ветка — 119 узлов. Полный запрос 6752 мс, decode/index 6672 мс, выборка 6 мс, heap worker 16 МиБ. Пик RSS процесса **118489088 байт**, RSS через 1 секунду после запроса 89653248 байт. Декодер укладывается в измеренный бюджет.
- Replay ранее захваченного реального снимка через настоящий collector/bridge/store/stdio: **45440 записей**, выбранная ветка **118 узлов**, decode/index 2040/2091 мс на первом/повторном запросе, выборка 4/4 мс, heap worker 21/17 МиБ. Наблюдаемый пик MCP **362741760 байт**, 295 отсчётов, ошибок наблюдателя нет. Это повтор ранее сохранённого трафика, не новая live-проверка браузера.

Общий лимит **500000000 байт** с расширением/CDP и Windows этим пунктом не принят; `fullImplementationBudgetAccepted=false`. Новый браузерный live-замер, большая выбранная ветка, серия смен selection и Windows остаются в TODO 19–20. Синтетический большой документ подтверждает ограниченную память при чтении всего снимка, но не охватывает все формы и размеры сетевых данных.
