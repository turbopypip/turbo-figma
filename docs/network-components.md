# Компоненты, instances и overrides (TODO 14)

Рабочий сетевой reader раскрывает поддержанное подмножество компонентов из
начального снимка. `components.representation: expanded-supported-subset` и
`complete: false` не позволяют принять результат за универсальный rendered tree.
Раскрытые instances имеют `component.definitionId`, `status: expanded` и источник
`captured-component` в context/debug. Этот статус подтверждает чтение master,
а не полноту всей семантики Figma.

## Поддержанные операции

- Адресное чтение master по symbolID/overriddenSymbolID из дискового индекса.
  Свойства экземпляра перекрывают master, дочернее дерево берётся из выбранного
  master. Swap использует потомков нового компонента.
- overrideKey и guidPath, вложенные scopes, derived overrides. Внутренние
  переопределения применяются раньше внешних, derived — после обычных в своём scope.
- Component properties: defaults, boolean (включая false), текст (включая пустую
  строку), swap. Assignments объединяются по definition ID.
- Видимость, parentId, порядок, глубина и пагинация раскрытых узлов. Дочерние ID
  имеют устойчивый instance/source path; это не временные ID браузерной сессии.

Отсутствие определения или неподдержанные структурные overrides дают
`instanceUnresolved`/`instanceError`. При невозможности раскрыть instance сырые
дочерние wire-записи не выдаются как его rendered children. Отсутствующая
component property тоже явно помечается. `traversal.unresolvedInstanceCount`
считает проблемы по всей обходимой ветке, включая узлы на других страницах;
обычный контекст не объявляет такой обход `complete: true`.

## Ограничения и незакрытая приёмка

Отдельными неподдержанными случаями остаются:

- отсутствующие/внешние masters и определения component properties;
- scale экземпляра, отличный от 1: запрос отклоняется;
- структурные удаления/переносы в overrides: instance не раскрывается;
- нераспознанные виды component properties, variable expressions/modes,
  slots и другие новые механизмы, не покрытые проверенной схемой;
- запрос непосредственно по производному instance/source ID: входная selection
  пока требует обычного nodeId; производные узлы читаются внутри ветки instance.

Циклы, глубина вложенных компонентов более 32 и превышение бюджета overrides
в 1 МиБ приводят к явной ошибке. Отсутствие ошибки не доказывает поддержку
произвольного файла Figma. Сценарий, использующий перечисленные возможности,
остаётся незакрытым критерием общей приёмки TODO 19; TODO 14 фиксирует проверенное
подмножество и явные ограничения, а не объявляет всю фичу принятой.

## Ресурсы

В одном запросе допускаются максимум 20000 адресных чтений зависимостей и
67108864 байта суммарных размеров прочитанных записей. Повторные чтения учитываются,
включая чтение для порядка дочерних узлов; проверка выполняется до чтения записи.
`components.dependencyReads/dependencyBytes` показывают расходы текущего обхода.
Это счётчик работы с зависимостями, не замер RSS.

Внешние masters и их потомки не добавляются в долгоживущий RAM-кэш selection.
Полный индекс остаётся на диске. Сохраняются ограничения selection cache,
соседей, глубины обхода и worker; общий бюджет памяти/Windows проверяется в TODO 20.

## Проверки

`tests/network-instances.test.mjs` покрывает nested precedence, overrideKey,
derived geometry, defaults, false/пустой текст, swap, отсутствующие definitions,
структурные overrides, циклы/глубину/scale, видимость, порядок, пагинацию,
отсутствие master в RAM-кэше и превышение бюджета при повторном чтении большого
компонента. Остальные тесты проверяют декодирование component values и MCP.

Контрольная ветка из TODO 11 повторно сопоставлена со всем сохранённым живым
UI-эталоном: имена, порядок, родители и layout. Сопоставление 59 сессионных ID
допустимо только после строгой проверки структуры. Ни один узел не исключается.
Для воспроизведения используется `scripts/check-network-layout.mjs`, как описано
в [network-layout.md](network-layout.md). Скрипт дополнен агрегатами компонентов.

Это replay ранее снятого UI-эталона, не новый живой обход Figma. Пустой текст,
отказ при структурных изменениях и ресурсный предел проверены синтетически;
наблюдение их в живом файле не заявляется. Обезличенные результаты:
[network-components-acceptance.json](network-components-acceptance.json).
