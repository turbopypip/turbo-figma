## Границы форматов

`layer=wire`: настоящая динамическая Kiwi-схема, Zstandard frames, managed NDJSON и legacy probe JSON. В синтетике Zstandard содержит **raw blocks**: эти данные проверяют корректность и границы, но не доказывают скорость распаковки сжатых production-данных.

`layer=model`: независимые от языка JSON-входы `nodes` и последовательные `live` batches для дискового индекса/преобразований. Они не подменяют wire-проверку instances/variables: соответствующие интеграционные случаи нужно расширить при реализации Rust-декодера. Реальный снимок уже содержит production-схему и контекст.

`*.expected.json` содержит стадии initial/live с полными последовательностями страниц либо точный текст ожидаемой ошибки. Golden-ответы сняты с N0; отдельные assertions проверяют смысловые инварианты (порядок, Unicode, hidden, overrides, effective variable width, unresolved и итог live), чтобы простое совпадение с N0 не считалось единственным доказательством корректности.

## Контракт differential-сравнения

Общая реализация: `scripts/rust-corpus/compare.mjs`.

1. Node.js и Rust читают **одни и те же сохранённые файлы**, предварительно сверенные по SHA-256, с одинаковым query и последовательностью live batches.
2. Сравнивается JSON-представление: порядок ключей объекта несущественен; порядок массивов/узлов, типы, числа, строки, идентичность снимка, revisions, completeness, unresolved и ошибки — точные. Числовые допуски не расширяются.
3. Нормализуются только `traversal.continuation` (непустой токен → маркер, null сохраняется) и верхнеуровневый `capturedAt` (валидная дата → маркер). Нельзя удалять все поля с именами time/token/id или сортировать массив узлов.
4. Сам токен используется для следующего запроса до нормализации. Коллектор проверяет движение offset, отсутствие дубликатов, число узлов относительно eligibleRecords и терминальный null. Проверка HMAC/привязки токена остаётся отдельной контрактной проверкой production, а не строковым сравнением разных подписей.
5. continuation=null означает конец страниц для заданной глубины, **не обязательно полное поддерево**. complete и pendingDepth сравниваются, а не игнорируются.
6. Диагностические свойства не удаляются автоматически. Если будущая реализация меняет диагностические счётчики, отличие сначала рассматривается явно; произвольное ослабление нормализации запрещено.
7. Offline probe и публичный observed context — разные адаптеры. Их ответы не следует сравнивать напрямую: freshness и серверные поля различаются. Rust должен запускаться с тем же адаптером/состоянием, что соответствующий golden.

Rust-реализации пока нет, поэтому сравнение N0/R не запускалось. Подготовлены общий вход, N0-ожидания и контракт для будущего стенда (этап 03).

## Команды

После `npm ci`:

```sh
npm run build
node scripts/rust-corpus/generate.mjs .cache/figma-network/rust-corpus-new
node scripts/rust-corpus/verify.mjs .cache/figma-network/rust-corpus-new
node --test tests/rust-corpus.test.mjs
npm run check
npm test
```

Генератор требует **новый** каталог, чтобы не перезаписать зафиксированный корпус. Полный synthetic replay проходит все страницы, в том числе за пределами кэша, и может занимать несколько минут.

Для замораживания уже полученного managed snapshot:

```sh
node scripts/rust-corpus/freeze.mjs /absolute/path/to/managed-generation .cache/figma-network/new-private-snapshot
```

Скрипт сверяет части с ready.json и копирует только части/manifest плюс создаёт probe. Не считать копию активным наблюдением: для публичного replay требуется корректная сессия capture; для offline использовать probe.

Проверка уже подготовленных наборов:

```sh
node scripts/rust-corpus/verify.mjs .cache/figma-network/rust-corpus-v1
node scripts/rust-corpus/verify.mjs .cache/figma-network/rust-corpus-real
```

## Проверки и ограничения

Self-review выполнен: общий seed, точные hashes, приватные выходные каталоги, неизменность production-кода, terminal null против complete, сохранение ошибок и semantic fields, сравнение нормализованного golden с сырым ответом.
Проверены воспроизводимость синтетических байтов, ошибки реального worker, независимые смысловые assertions, отказ на испорченной части при freeze и отсутствие копирования config.
`npm run check` прошёл; итоговый `npm test` — **289/289**, целевые тесты — **6/6**. Проверка SHA-256 прошла для 45 файлов синтетического и 19 файлов реального корпуса. `git diff --check` прошёл.

Производительность и RAM здесь не измерялись; прогоны шли на текущей машине без изоляции нагрузки. Windows и сравнительный Rust-run не выполнялись. Существующие ограничения поддержки live, instances и variables не изменены.

### Уточнение при профилировании этапа 04

Реальные golden-ответы были сняты с UI-kit из локальной настройки сервера:
`variableMatching.fingerprint=0feef4b502d65252f735aa6bcbf6c8303841f23f45cff02de5d04ea5bd413537`.
Поле query в manifest не содержит этот неявный параметр. Для воспроизведения
именно этих ответов требуется передать тот же UI-kit явно; без него меняются
свойства и число страниц. В этапе 04 его байты сохранены локально рядом с корпусом
как `profile-ui-kit.variables.scss`, путь передаётся через `--variables-file`.
Исходные manifest/golden не переписывались. Полный набор для передачи теперь должен
включать и этот файл; при другой таблице переменных golden-ответы не эквивалентны.
