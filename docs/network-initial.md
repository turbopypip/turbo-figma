# Полный начальный снимок и восстановление (TODO 06)

## Пользовательский сценарий

Подключи расширение к MCP на нужной вкладке. «Начать сетевой захват» подключает debugger без перезагрузки: если поток уже открыт, начало может отсутствовать. Popup показывает это ограничение. Отсутствующая схема, оборванный поток и таймаут дают ошибку с указанием повторного захвата.

Для восстановления останови незавершённый захват, нажми «Подключить», затем **«Перезагрузить и захватить»**. Эта отдельная кнопка явно предупреждает о перезагрузке текущей подключённой вкладки Figma. Сначала создаётся новое поколение, подключается debugger и включается перехват, затем вызывается `chrome.tabs.reload`. Собственная перезагрузка допускает повторные loading/complete при запуске Figma worker до завершения начального потока. Смена файла, закрытие multiplayer-соединения или его worker-сессии отменяют захват; общий дедлайн ограничивает ожидание. Одни уведомления loading/complete при собственном reload не доказывают отдельную внешнюю перезагрузку. Другие вкладки не перезагружаются.

В режиме восстановления новые worker/iframe приостанавливаются через `waitForDebuggerOnStart`, получают `Network.enable` и рекурсивный auto-attach, затем продолжают работу через `Runtime.runIfWaitingForDebugger`. Дочерние сессии прежней загрузки без наблюдаемого multiplayer-потока можно отключить без ложного отказа восстановления. Потеря сессии уже наблюдаемого потока остаётся ошибкой.

## Критерий готовности

В `src/network-initial.ts` MCP разбирает NDJSON по мере поступления частей, включая записи на границе файлов. Для всех захватов через мост применяется этот инспектор; клиентские флаги `evidence` сами по себе не дают права опубликовать снимок.

Один начальный поток должен содержать:

1. Канонический base64 бинарного `fig-wire` v1 со схемой Kiwi в Zstandard.
2. Один `JOIN_START` до начальных данных.
3. Начальные `NODE_CHANGES` с верхнеуровневыми записями `CREATED`.
4. `JOIN_END` после хотя бы одной записи узла.

Проверяются единая пара debugger-session/requestId, последовательные `eventSequence` от нуля, порядок частей и точное число сохранённых частей. Повторы, пропуски наблюдаемых событий, смешение потоков, текстовые/неподдержанные фреймы, повреждение данных, неполная строка и незавершённый join отклоняются. Сообщения после JOIN_END не добавляются к начальному снимку.

Инспектор компилирует схему только для маркеров: узлы посещаются, но массив документа и индекс не сохраняются. Вложенные NodeChange (например, overrides) не считаются отдельными верхнеуровневыми CREATED-узлами. Это проверка границ начального потока, а не восстановление дерева, раскрытие компонентов или доказательство визуальной полноты.

Подтверждение последней части содержит `initial.initialComplete`. Сборщик прекращает запись начального потока и отправляет `finish`, сохраняя debugger для наблюдения. Сообщения, уже стоящие в очереди после границы начальной загрузки или пришедшие во время finish, инвалидируют захват; тихого отбрасывания с публикацией ready нет. Сервер заново проверяет завершённость инспектора и атомарно публикует метаданные через NetworkStore. Только ответ на finish переводит popup в `ready`/`complete: true`. Ручное скачивание JSON не требуется; данные лежат в `.cache/figma-network/`.

Готовый снимок представляет состояние **на момент начальной загрузки**, а не текущий живой документ. [актуальность и восстановление](network-freshness.md). Основной `get_design_context` ещё не переключён на эти данные (TODO 18).

## Лимиты и ошибки

Сохранены лимиты TODO 04: часть 256 КиБ и 10000 частей. Для наблюдавшегося реального пакета расширены ограничения TODO 05: payload до 8 Ми символов, очередь до 16 МиБ/64 записей, NDJSON-запись до 16 МиБ. Схема распаковывается максимум до 2 МиБ, сообщение — до 64 МиБ, начальных узлов — до 200000. Переполнение завершает захват явно. Эти значения ограничивают отдельные буферы, но не доказывают общий расход RAM <=500000000 байт.

Расширение ограничивает весь начальный захват двумя минутами; сервер сохраняет 30-секундный таймаут между командами/на запись. При зависшем attach вызывающий код получает отмену по таймауту, а позднее успешное подключение debugger снимается. Отказ attach/reload/worker-настройки/detach и обрыв транспорта видны в состоянии. Ошибка до публикации не создаёт ready.json; штатная очистка удаляет незавершённые поколения.

CDP не предоставляет здесь сквозной счётчик сервера Figma: eventSequence обнаруживает пропуски между сборщиком и инспектором, но не доказывает отсутствие невидимой потери событий внутри браузера. Полный контроль над неподдерживаемыми вариантами протокола, RAM и тяжёлым декодированием остаётся в TODO 07–08; независимая сверка содержимого — TODO 19. Инспектор пока работает в процессе MCP и использует существующий Kiwi-декодер. Новых зависимостей нет.

## Проверки

`npm run check` и `npm test` проверяют валидный поток, разбиение записей, неподтверждённый finish, ошибки порядка/формата, вложенные overrides, восстановление и worker, дедлайн, отмену и поздний attach. Интеграционный тест использует модель Chrome API, настоящий WebSocket, NetworkStore и проверяет готовый manifest без ручного дампа.

Существующий реальный probe v2 с нулём dropped прошёл отдельно через тот же инспектор: 7 входящих сообщений до JOIN_END, 24 части; максимальный payload в проверенном начальном потоке — 4633720 символов. Приватные данные не добавлены в Git. Повторная проверка после `npm run build`:

```sh
node scripts/check-initial-capture.mjs /absolute/path/to/existing-probe.json
```

Этот диагностический скрипт читает старый ручной JSON целиком и печатает только счётчики; рабочий сборщик этого не делает. Новый полный прогон в Chrome/Figma, Windows и общий RAM-бюджет этим этапом не приняты.
