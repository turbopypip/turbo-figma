# Перенос проверенных частей MCP на Rust

Дата: 26 октября 2026. Платформа локальной проверки: macOS arm64, Node 20.12.2, Rust 1.99.1.

## Дополнение: Windows и мультиплатформенный запуск

26 октября 2026: добавлен Windows MSVC вариант общего standalone runtime. `platform.rs` изолирует Windows RNG (BCrypt), UTC, console control, идентичность файлов/каталогов и нормализацию путей. Unix-реализации сохранены. Для Windows `fsync` каталогов не выполняется; содержимое файлов и manifest сбрасывается перед публикацией. Индекс закрывает файловые handles до удаления scratch. Node использует bigint stamps, чтобы не округлять Windows file IDs. Launcher/setup выбирают `.exe` и native backend на Windows; явный Node fallback сохранён, старый Unix socket MCP bridge на Windows не используется.

Добавлен `install.ps1`: Node, MSVC C++/SDK, Rust 1.99.1, npm dependencies, обе сборки и setup. Windows CI дополнен коротким MCP smoke со сборкой TypeScript. По запросу пользователя полный набор и Windows-приёмка не выполнялись. На macOS прошли release build, `npm run check`, `npm run build` и MCP smoke 2/2. Windows MSVC target прошёл `cargo check` (без линковки Windows executable; для проверки Rust использован host zstd через pkg-config). Это не результат запуска `.exe` или PowerShell-установщика на Windows. Метрики CPU/RSS и полная приёмка остаются отдельной работой.

## Текущий результат: автономный сервер Rust

Серверный runtime на macOS перенесён в Rust, включая ранее остававшиеся Node-части. `figma-rust-helper --server CONFIG INSTALLATION` обслуживает MCP и расширение **без Node-процесса и без Node tool host**. Проверяется отдельным прямым stdio-тестом. Старый список неперенесённых частей ниже — история предыдущих итераций.

- `traversal.rs`, `instances.rs`, `geometry.rs`: полный поддержанный обход, ancestor geometry, instances, overrides, вложенные масштабы и component properties, порядок, скрытые ветки, dependency budgets и страницы.
- `variable_resolver.rs`, `bindings.rs`, `uikit.rs`: captured modes/defaults/aliases, применение значений до layout/styles, диагностика unresolved и UI-kit. CSS/SCSS читаются ограниченно; Sass не исполняется. Для развернутых значений UI-kit добавлен отдельный предел 2 МиБ. Сокращение длинных имён учитывает UTF-16 и не разрезает Unicode-символ.
- `inspector.rs`, `engine.rs`: доказательства initial load, sequence/ACK, публикация manifest, capture ownership, presence/selection, supported live changes, revision/freshness, reader/writer exclusion, integrity recheck на cache hit, HMAC continuation, отмена и освобождение scratch. Один ограниченный actor владеет файловыми операциями и индексом; очистка не пересекается с чтением. Heartbeat проверенной сессии обновляет lease независимо от тяжёлой работы. Idle timer освобождает индекс через 60 секунд без новых tool calls; release обновлённого индекса требует recapture.
- `standalone.rs`: нативные обработчики пяти публичных MCP-инструментов, pairing, WebSocket, timeout/cancellation, PNG/SVG и shutdown по EOF/SIGTERM. Неизвестные live-поля/частичные ошибки инвалидируют наблюдение; незавершённый capture не публикуется. Лимит WebSocket — 6 МиБ, соединений/tool calls — восемь; браузерных операций одновременно одна. Тяжёлые чтения и capture имеют исключение, а не неограниченную очередь.
- Кэш готовых страниц использует **тот же** лимит проекций 128 записей / 4 МиБ и сбрасывается при select/invalidate/upsert/remove/live. Кэш исходных узлов остаётся ограниченным 4 МиБ. Полная проверка SHA-256 частей перед повторным чтением сохранена.
- `src/index.ts` — совместимый launcher, выбирающий Rust либо fallback; прежний entrypoint сохранён в `fallback-entry.ts`. Setup при наличии сборки генерирует прямую команду Rust. Браузерное расширение остаётся JavaScript, поскольку использует browser/DOM API. Node-реализация сохранена для отката и диагностических сравнений, но не вызывается автономным Rust-сервером.

Новых Cargo/NPM-зависимостей нет. Ошибка уже запущенного native-сервера не вызывает повтор операции в Node. При отсутствии бинарника launcher выбирает fallback; явно выбрать его можно через `FIGMA_NETWORK_BACKEND=node`. При прямой команде бинарника откат требует заменить команду на Node launcher.

## Дополнение: layout, стили и публичные узлы

**Полный перенос MCP ещё не завершён.** В этой итерации в рабочий Rust-путь перенесены расчёт layout, визуальные стили/типографика и публичное представление узла. Node по-прежнему выполняет обход и ancestor geometry, раскрытие instances/overrides/scale, разрешение native variables, UI-kit, pagination/continuation, lifecycle/read leases, pairing/capture coordination и обработчики инструментов. Точка входа остаётся Node; наличие native layout не означает полностью нативный сервер.

- `layout.rs`: размеры, Auto Layout, sizing evidence, constraints, bounds, inspector и порядок CSS. `angle.rs` сохраняет поведение atan/atan2 эталонного Node 20/V8, включая последние биты углов; источник и разрешительная лицензия fdlibm сохранены в файле.
- `style.rs`: fills/strokes/effects, прозрачность, радиусы, шрифты и смешанные текстовые диапазоны UTF-16. Сохранены коллекционные/байтовые лимиты, диагностика неизвестных значений и запрет границ внутри суррогатных пар. Разрешённые значения переменных пока приходят из Node.
- `context.rs`: allowlist публичного узла, панель свойств, объединение CSS и удаление внутренних данных native bindings. Debug сохраняет исходные свойства. Слишком большой результат заменяется прежней краткой записью; Unicode-обрезка имени остаётся на границе Node.
- Пакеты проекций ограничены восемью узлами; накопление запросов сбрасывается при 128 КиБ, одиночный запрос сохраняет транспортный лимит 2 МиБ. Запрос передаёт ID и эффективные изменения; исходный узел берётся из Rust-индекса. Результат команды ограничен 3 МиБ внутри общего ответа 4 МиБ.
- Native кэш сериализованных проекций: не более 128 пакетов / 4 МиБ с учётом capacity строк и накладного заряда на запись. Это дополнительный кэш к прежним 4 МиБ исходных узлов. Он сбрасывается при select/invalidate/upsert/remove/live. Ключ SHA-256 включает формат, schema, лимит записи, effective patch, bindings, parent и geometry. Ошибки не кэшируются.
- На повторном чтении manifest и полная проверка SHA-256 частей выполняются в уже удерживаемом Rust-процессе. Проверки identity, canonical path/inode и read lease сохранены. Эта команда допускает только verify, не запись; отмена завершает и дожидается процесса. Общая state machine пока остаётся Node.

Новых Cargo/NPM-пакетов эта итерация не добавляет. Допуск пользователя на больший расход CPU учтён как разрешение оптимизировать время ответа; CPU/RAM-приёмка этим не заменяется.

Проверки этой итерации: release build и TypeScript/extension check; Cargo 3/3. Добавлены дифференциальные проверки layout/styles/public nodes, поворотов, CSS-порядка, суррогатных пар, лимитов, immutable effective patches, invalidation кэша, повреждения частей и отмены удерживаемого процесса. Сравнение всех страниц реальной записи с Node сохранено. Тест гонки live/read и профайлер переведены на новый путь verify без ослабления проверок.

Полный native-набор **348/348**, Node fallback **348/348**, без пропусков. После обновления test hooks и профайлера отдельно повторены fallback live/profile **48/48**. Начальный native-прогон выявил, что тест гонки ожидал больше не вызываемый метод, а профайлер не учитывал новый verify; они исправлены, полный native-набор повторён и штатно завершился. `git diff --check` прошёл.

Финальный [диагностический замер](rust-runtime-context-results.json): три чередующихся прогона на backend/selection, все страницы с UI-kit, без одновременных сборок и тестов. Корректность сравнивается отдельными тестами, эта серия измеряет только время reader. Медианы:

## Предыдущее дополнение: storage, live, ассеты и транспорты

Следующая часть переноса реализована и подключена на macOS. **Весь перенос ещё не завершён:** геометрия/layout/styles/instances/variables/UI-kit, управление lifecycle и обработчики инструментов остаются в Node. Наличие Rust MCP-транспорта не означает, что вся серверная логика уже нативная.

- `store.rs`: файловые операции NetworkStore — создание поколения/ownership marker, эксклюзивная запись частей и SHA-256, fsync, подготовка/атомарная публикация manifest, ограниченное чтение, проверка всех частей, inventory, retention и clean. В Node остаются state machine, доказательства завершения, счётчики sequence/total, BUSY/read leases, отмена и observation. Корни и поколения проверяются по canonical path и inode; неизвестные файлы и hardlinks защищены от удаления.
- `live.rs`, `wire.rs`, `disk.rs`: строгий Kiwi-декодер поддержанного live-подмножества, проверки полей/чисел/типов, создание/удаление, ancestry/cycle checks, лимиты batch и окончательная блокировка индекса после ошибки. Native worker больше не декодирует live в Node. Service/presence classification, sequence/ACK, freshness и координация всё ещё Node.
- `assets.rs`: проверка canonical base64, лимитов и сигнатуры PNG/признака SVG, NFKC-имена, случайные плоские имена, эксклюзивная запись 0600 и удаление неполного файла. Это сохраняет прежнюю ограниченную проверку формата, не добавляет SVG-санитизацию. В Rust генераторе имён используется Unicode alphanumeric; редкие знаки и границы astral-символов могут давать другой stem, имена и раньше были случайными.
- `websocket.rs`: Rust слушает только 127.0.0.1, выполняет WebSocket handshake/framing, ограничивает сообщения/frames 6 МиБ и соединения восемью, выключает compression (не подключён), ограничивает IPC и время handshake. Node Bridge сохраняет pairing, статус, pending requests и capture handlers. У протокола остаётся прежний close code 1009 для превышения размера.
- `mcp.rs`: rmcp обслуживает stdio, initialization, discovery и dispatch/cancellation. Node передаёт определения инструментов и выполняет существующие проверенные обработчики через приватный Unix socket. Вход аргументов ограничен 64 КиБ, одновременно допускается восемь tool calls. EOF, отключение host и shutdown завершают подпроцессы. В диагностике запуска есть `MCP stdio backend: rust`.

Новые зависимости согласованы пользователем и проверены до подключения: tokio **1.54.1**, tokio-tungstenite **0.30.0**, rmcp **3.7.0**, unicode-normalization **0.1.26**, futures-util **0.3.34**. Все прямые версии закреплены. HTTP/OAuth/TLS-клиентские features не включены. Итоговый Cargo.lock: **102 registry-пакета, 0 известных OSV advisories** на дату проверки. Подробности и ограничения аудита: [rust-dependency-security.md](rust-dependency-security.md).

Проверки: release build, TypeScript/extension check, полный native-набор **342/342**, полный Node fallback-набор **342/342**, Cargo **3/3**. После исправления TCP close/RST гонки полный native-набор повторён: **342/342**, без пропусков. Сквозной MCP-тест запускает Rust helper и подтверждает native stdio, discovery/context/image/export/EOF. Новые тесты покрывают native store failures/cancellation, hardlinks/corruption, asset validation и native live rejection/poisoning. Живой браузер/Kilo и Windows не проверены, общий RAM-бюджет не принят.

Он получает только ограниченные данные для текущего вычисления контекста. Сохранённый Node-путь нужен для совместимости и отката; удалять его до переноса остальных функций и приёмки рано.

## Как подключено

- `src/network-rust.ts` запускает один helper на удерживаемый индекс. Его владельцем является основной MCP-процесс, поэтому принудительное завершение projection-worker не оставляет helper без управления.
- `rust/helper/src/stage8.rs` добавляет `--stage8 runtime CONFIG`: initial input → Zstandard → Kiwi → индекс, затем последовательные ограниченные команды по stdin/stdout. Контракт runtime имеет версию 1; диагностический вывод отделён от ответов.
- `src/network-disk.ts` сохраняет действующую проекцию контекста, но в native-режиме её операции хранения выполняет Rust. Node не открывает native index-файлы.
- `src/network-rust-storage.ts` связывает синхронную проекцию worker с асинхронным основным процессом. Один запрос в работе; дополнительной очереди команд нет. Общий буфер ответов ограничен 4 МиБ, вход команды — 2 МиБ.
- Для повторных страниц read-only обращения объединяются в batch: до 512 команд и до 1 МиБ сериализованных значений. Между проекциями Node запоминает только команды (не более 64 КиБ их JSON). Временные значения текущей проекции ограничены зарядом 4 МиБ и очищаются после неё. Авторитетный retained-кэш находится в Rust, с прежними лимитами 2048 узла / 4 МиБ.
- Готовый индекс переиспользуется на следующих страницах. Смена selection/generation, ошибка, отмена, shutdown и idle TTL освобождают helper и scratch. Read lease защищает снимок и во время native-загрузки. Проверка частей на cache hit остаётся прежней Node-проверкой.
- Ошибка native-загрузки до публикации результата удаляет весь частичный индекс и запускает прежний Node-путь. Это сохраняет совместимость с допустимыми для JSON.parse/fzstd входами, которые native-библиотеки отвергают. Отмена и timeout не запускают повтор; после публикации индекса или live-изменений скрытого повторного чтения исходного снимка нет.
- Legacy `captureFile` остаётся на Node. Windows по умолчанию остаётся на Node до этапа 15.

Команды Rust-хранилища для live — новая интеграционная работа. Они проверены вместе с существующим live-контрактом, но не означают полного переноса live/lifecycle в Rust.

## Сборка и использование

```sh
npm run build:rust
npm run build
npm start
```

`build:rust` использует установленный в `.local` toolchain, если он есть, иначе Cargo из PATH. Проверенная версия — Rust 1.99.1, зависимости закреплены Cargo.lock. При запуске готового бинарника Cargo не требуется. После обновления нужно перезапустить уже работающий MCP.

- `FIGMA_NETWORK_BACKEND=rust`: выбрать native managed-путь с compatibility fallback.
- `FIGMA_NETWORK_BACKEND=node`: явно вернуть прежнюю реализацию.
- `FIGMA_RUST_BINARY`: при необходимости указать путь к собственному собранному helper.
- Debug-ответ: `metrics.backend`, `metrics.rustFallback`, `metrics.rustPid`. Обычный context не содержит этих внутренних диагностик.

При отсутствии бинарника срабатывает Node fallback. Поэтому наличие новой версии исходников само по себе не доказывает native-исполнение: сборка и debug-метрика должны подтверждать `backend: rust` без `rustFallback`.

## Проверки

- Release build, `npm run check`, Cargo unit tests: **3/3**.
- Полный набор с `REQUIRE_RUST_HELPER=1 FIGMA_NETWORK_BACKEND=rust`: **338/338**, без пропусков. После финального уточнения двух байтов бюджета batch отдельно повторены runtime-тесты: **6/6**, без пропусков.
- Новые runtime integration-тесты сравнивают public context и debug с Node на wire-корпусе, включая 4097 узлов, Unicode, глубокие и скрытые ветки, пагинацию и cache reuse. Проверяется именно `backend: rust`, а не успешный fallback.
- На реальной локальной записи сравнены все страницы компонента 5 узлов и секции 39 узлов. Нормализация исключает только ожидаемо разные метрики и HMAC continuation; содержимое страниц, порядок, ограничения, dependency accounting и полнота сравниваются полностью.
- Проверены native live storage updates, создание/удаление и перенос между родителями, порядок, bounded batch, запрет write-команд внутри read batch, отсутствующие узлы, отсутствующий бинарник и JSON compatibility fallback.
- Проверены отмена во время чтения, аварийное завершение helper, reaping PID и удаление scratch. Полный набор включает действующие bridge/live/freshness/continuation-тесты.
- Self-review: границы памяти/пакетов, отсутствие второго индекса, сохранение live-валидации, отсутствие replay после live, ownership subprocess, отмена и cleanup. Исправлены лишняя мелкая IPC-передача, повторная JSON-пересериализация и учёт native-загрузки в диагностическом времени.

Живой браузер/Kilo, Windows и удалённый CI в этой работе не запускались. Непрерывный soak-тест и полный одновременный бюджет 500000000 байт, включая расширение, ещё не подтверждены. Исторические результаты этапов 06–08 не подменяют эти проверки.

## Измерение интеграции

Воспроизведение: `node scripts/rust-helper/runtime-measure.mjs` после сборки, при наличии локального реального корпуса. Три прогона на backend/selection, чередование порядка, один Node-host, новый retained index на каждый cold-прогон, все страницы context с UI-kit. Без принудительного GC. CPU/RAM не измерялись. Это диагностическая серия, а не приёмка этапа 13.

[Итоговая серия](rust-runtime-results.json) содержит сырые времена и медианы. [Первый замер до batch](rust-runtime-before-batching.json) сохранён отдельно: он выявил замедление повторного обхода секции до 668.5 мс против 176.2 мс у Node. Пакетное чтение и устранение лишней JSON-пересериализации добавлены по результатам этого измерения.

Медианы итоговой диагностической серии:

**Остаётся warm-регрессия секции:** 14.4% превышает исходный допуск 5%. Этап 13 не принят, и интеграция не объявляется быстрее во всех сценариях. Основная задача для её устранения — перенести в Rust полную проекцию и пагинацию, убрав стоимость межпроцессных lookup. Выигрыш холодного пути не означает автоматического выигрыша каждой прогретой страницы. Оставшаяся стоимость IPC должна уходить по мере переноса полной проекции контекста в Rust.

## Что осталось переносить

1. **08б — файловый NetworkStore:** generation/begin/append/commit/abort, fsync и атомарная публикация, inventory, retention/prune/clean. R01 уже читает снимок в Rust; запись/управление хранилищем ещё не перенесены.
2. **09 — полный контекст:** геометрия, Auto Layout, styles/text/fonts, instances/overrides/component properties, native variable modes/defaults/aliases, UI-kit matching, обход с вычислением контекста. После этого отпадут временные обращения Node-проекции к Rust-индексу.
3. **10 — владение lifecycle:** coordinator/read leases/BUSY, reader-writer exclusion, invalidation, TTL, continuation и полный response byte budget. Удержание Rust-индекса уже интегрировано, но управляется Node.
4. **11 — серверный capture/live:** strict live decoding и валидация, observation/freshness/revision, selection, heartbeat/reconnect, sequence/ack/backpressure и связка screenshot → context. Rust-персистенция live-узлов не закрывает этот этап.
5. **12 — сервер и ассеты:** MCP stdio, WebSocket, публичные инструменты/ошибки/авторизация, PNG/SVG/base64/файловые ограничения. Legacy reader и compatibility fallback также остаются явными техническими долгами до эквивалентной замены.
6. **13–16 — приёмка и завершение:** сквозная скорость/CPU/RAM на macOS, реальные браузер/Kilo, чистая установка и поставка, Windows-приёмка, удаление заменённого Node-кода и зависимостей. Текущее включение частей на macOS не закрывает все критерии этапа 14.

Новых сторонних зависимостей для runtime-интеграции не добавлено. Коммит включает ранее накопленные реализации и отчёты этапов 06–08, новую рабочую интеграцию, тесты и этот статус. Приватные captures, `.local`, собранные бинарники и временные артефакты в Git не включаются.
