# Перенос проверенных частей MCP на Rust

Дата: 26 октября 2026. Платформа локальной проверки: macOS arm64, Node 20.12.2, Rust 1.99.1.

## Результат

Проверенные реализации R01–R04 теперь вызываются рабочим managed MCP-путём `readStoredNetworkSnapshot`, а не только сравнительными скриптами. На macOS этот путь выбирает Rust по умолчанию. Полностью нативного MCP-сервера пока нет: Node обслуживает протоколы и вычисляет дизайн-контекст поверх Rust-хранилища.

| Часть | Текущее исполнение |
| --- | --- |
| Чтение managed manifest/частей, проверка identity/sequence/размеров/SHA-256, NDJSON/base64 | Rust, существующий R01 |
| Ограниченная распаковка Zstandard | Rust, существующий R02 |
| Схема и ограниченный Kiwi-декодер начального снимка | Rust, существующий R03 |
| Построение дискового индекса, node log, связи, порядок дочерних узлов, индекс variable assets | Rust, существующий R04 |
| Поиск узлов/зависимостей и ограниченный retained selection-кэш | Rust, оптимизированный R04 |
| Raw traversal | Реализован в Rust; публичный обход с раскрытием instances и вычислением контекста ещё выполняет Node |
| Запись поддержанных live-изменений, удаление/перепривязка узлов и сброс native-кэша | Rust storage-команды; декодирование, валидация и координация live пока Node |
| Полный дизайн-контекст, layout/styles/instances/variables/UI-kit | Node, использует Rust lookup/children/asset вместо Node-файлов |
| NetworkStore: запись и публикация снимков, retention/clean, read leases | Node |
| MCP stdio, WebSocket, capture/freshness, continuation, таймеры, PNG/SVG | Node |
| Chrome-расширение и browser/DOM API | JavaScript |

На нормальном Rust-пути Node больше не декодирует весь initial snapshot, не строит параллельный дисковый индекс и не хранит прежний retained selection-кэш. Он получает только ограниченные данные для текущего вычисления контекста. Сохранённый Node-путь нужен для совместимости и отката; удалять его до переноса остальных функций и приёмки рано.

## Как подключено

- `src/network-rust.ts` запускает один helper на удерживаемый индекс. Его владельцем является основной MCP-процесс, поэтому принудительное завершение projection-worker не оставляет helper без управления.
- `rust/helper/src/stage8.rs` добавляет `--stage8 runtime CONFIG`: initial input → Zstandard → Kiwi → индекс, затем последовательные ограниченные команды по stdin/stdout. Контракт runtime имеет версию 1; диагностический вывод отделён от ответов.
- `src/network-disk.ts` сохраняет действующую проекцию контекста, но в native-режиме её операции хранения выполняет Rust. Node не открывает native index-файлы.
- `src/network-rust-storage.ts` связывает синхронную проекцию worker с асинхронным основным процессом. Один запрос в работе; дополнительной очереди команд нет. Общий буфер ответов ограничен 4 МиБ, вход команды — 2 МиБ.
- Для повторных страниц read-only обращения объединяются в batch: до 512 команд и до 1 МиБ сериализованных значений. Между проекциями Node запоминает только команды (не более 64 КиБ их JSON). Временные значения текущей проекции ограничены зарядом 4 МиБ и очищаются после неё. Авторитетный retained-кэш находится в Rust, с прежними лимитами 2048 узла / 4 МиБ.
- Готовый индекс переиспользуется на следующих страницах. Смена selection/generation, ошибка, отмена, shutdown и idle TTL освобождают helper и scratch. Read lease защищает снимок и во время native-загрузки. Проверка частей на cache hit остаётся прежней Node-проверкой.
- Ошибка native-загрузки до публикации результата удаляет весь частичный индекс и запускает прежний Node-путь. Это сохраняет совместимость с допустимыми для JSON.parse/fzstd входами, которые native-библиотеки отвергают. Отмена и timeout не запускают повтор; после публикации индекса или live-изменений скрытого повторного чтения исходного снимка нет.
- Legacy `captureFile` остаётся на Node. Windows по умолчанию остаётся на Node до этапа 15.

Команды Rust-хранилища для live — новая интеграционная работа. Они проверены вместе с существующим live-контрактом, но не означают полного переноса live/lifecycle в Rust.

## Сборка и использование

```sh
npm run build:rust
npm run build
npm start
```

`build:rust` использует установленный в `.local` toolchain, если он есть, иначе Cargo из PATH. Проверенная версия — Rust 1.99.1, зависимости закреплены Cargo.lock. При запуске готового бинарника Cargo не требуется. После обновления нужно перезапустить уже работающий MCP.

- `FIGMA_NETWORK_BACKEND=rust`: выбрать native managed-путь с compatibility fallback.
- `FIGMA_NETWORK_BACKEND=node`: явно вернуть прежнюю реализацию.
- `FIGMA_RUST_BINARY`: при необходимости указать путь к собственному собранному helper.
- Debug-ответ: `metrics.backend`, `metrics.rustFallback`, `metrics.rustPid`. Обычный context не содержит этих внутренних диагностик.

При отсутствии бинарника срабатывает Node fallback. Поэтому наличие новой версии исходников само по себе не доказывает native-исполнение: сборка и debug-метрика должны подтверждать `backend: rust` без `rustFallback`.

## Проверки

- Release build, `npm run check`, Cargo unit tests: **3/3**.
- Полный набор с `REQUIRE_RUST_HELPER=1 FIGMA_NETWORK_BACKEND=rust`: **338/338**, без пропусков. После финального уточнения двух байтов бюджета batch отдельно повторены runtime-тесты: **6/6**, без пропусков.
- Новые runtime integration-тесты сравнивают public context и debug с Node на wire-корпусе, включая 4097 узлов, Unicode, глубокие и скрытые ветки, пагинацию и cache reuse. Проверяется именно `backend: rust`, а не успешный fallback.
- На реальной локальной записи сравнены все страницы компонента 5 узлов и секции 39 узлов. Нормализация исключает только ожидаемо разные метрики и HMAC continuation; содержимое страниц, порядок, ограничения, dependency accounting и полнота сравниваются полностью.
- Проверены native live storage updates, создание/удаление и перенос между родителями, порядок, bounded batch, запрет write-команд внутри read batch, отсутствующие узлы, отсутствующий бинарник и JSON compatibility fallback.
- Проверены отмена во время чтения, аварийное завершение helper, reaping PID и удаление scratch. Полный набор включает действующие bridge/live/freshness/continuation-тесты.
- Self-review: границы памяти/пакетов, отсутствие второго индекса, сохранение live-валидации, отсутствие replay после live, ownership subprocess, отмена и cleanup. Исправлены лишняя мелкая IPC-передача, повторная JSON-пересериализация и учёт native-загрузки в диагностическом времени.

Живой браузер/Kilo, Windows и удалённый CI в этой работе не запускались. Непрерывный soak-тест и полный одновременный бюджет 500000000 байт, включая расширение, ещё не подтверждены. Исторические результаты этапов 06–08 не подменяют эти проверки.

## Измерение интеграции

Воспроизведение: `node scripts/rust-helper/runtime-measure.mjs` после сборки, при наличии локального реального корпуса. Три прогона на backend/selection, чередование порядка, один Node-host, новый retained index на каждый cold-прогон, все страницы context с UI-kit. Без принудительного GC. CPU/RAM не измерялись. Это диагностическая серия, а не приёмка этапа 13.

[Итоговая серия](rust-runtime-results.json) содержит сырые времена и медианы. [Первый замер до batch](rust-runtime-before-batching.json) сохранён отдельно: он выявил замедление повторного обхода секции до 668.5 мс против 176.2 мс у Node. Пакетное чтение и устранение лишней JSON-пересериализации добавлены по результатам этого измерения.

Медианы итоговой диагностической серии:

| Сценарий | Node | Rust + Node-проекция | Изменение |
| --- | ---: | ---: | ---: |
| Компонент, первый cold-ответ | 1675.3 мс | 1045.8 мс | −37.6% |
| Компонент, все cold-страницы | 1685.5 мс | 1058.9 мс | −37.2% |
| Компонент, все warm-страницы | 18.5 мс | 19.2 мс | +3.8%, +0.7 мс |
| Секция, первый cold-ответ | 1668.5 мс | 1067.0 мс | −36.1% |
| Секция, все cold-страницы | 1849.6 мс | 1269.7 мс | −31.4% |
| Секция, все warm-страницы | 178.8 мс | 204.5 мс | +14.4%, +25.7 мс |

**Остаётся warm-регрессия секции:** 14.4% превышает исходный допуск 5%. Этап 13 не принят, и интеграция не объявляется быстрее во всех сценариях. Основная задача для её устранения — перенести в Rust полную проекцию и пагинацию, убрав стоимость межпроцессных lookup. Выигрыш холодного пути не означает автоматического выигрыша каждой прогретой страницы. Оставшаяся стоимость IPC должна уходить по мере переноса полной проекции контекста в Rust.

## Что осталось переносить

1. **08б — файловый NetworkStore:** generation/begin/append/commit/abort, fsync и атомарная публикация, inventory, retention/prune/clean. R01 уже читает снимок в Rust; запись/управление хранилищем ещё не перенесены.
2. **09 — полный контекст:** геометрия, Auto Layout, styles/text/fonts, instances/overrides/component properties, native variable modes/defaults/aliases, UI-kit matching, обход с вычислением контекста. После этого отпадут временные обращения Node-проекции к Rust-индексу.
3. **10 — владение lifecycle:** coordinator/read leases/BUSY, reader-writer exclusion, invalidation, TTL, continuation и полный response byte budget. Удержание Rust-индекса уже интегрировано, но управляется Node.
4. **11 — серверный capture/live:** strict live decoding и валидация, observation/freshness/revision, selection, heartbeat/reconnect, sequence/ack/backpressure и связка screenshot → context. Rust-персистенция live-узлов не закрывает этот этап.
5. **12 — сервер и ассеты:** MCP stdio, WebSocket, публичные инструменты/ошибки/авторизация, PNG/SVG/base64/файловые ограничения. Legacy reader и compatibility fallback также остаются явными техническими долгами до эквивалентной замены.
6. **13–16 — приёмка и завершение:** сквозная скорость/CPU/RAM на macOS, реальные браузер/Kilo, чистая установка и поставка, Windows-приёмка, удаление заменённого Node-кода и зависимостей. Текущее включение частей на macOS не закрывает все критерии этапа 14.

Новых сторонних зависимостей для runtime-интеграции не добавлено. Коммит включает ранее накопленные реализации и отчёты этапов 06–08, новую рабочую интеграцию, тесты и этот статус. Приватные captures, `.local`, собранные бинарники и временные артефакты в Git не включаются.
