## Исправление чтения, 25 октября 2026

Причина оказалась шире одного SIGNAL: после JOIN_END штатно приходят `reconnect-key`, `reconnect-sequence-number`, CLIENT_BROADCAST (состояние совместной сессии), USER_CHANGES (присутствие), а браузер отправляет CLIENT_RENDERED и периодический USER_CHANGES heartbeat с transport-метаданными. Прежний код либо требовал idle-индекс, либо отклонял следующий пакет, пока предыдущий ожидал ACK. Первые исправленные попытки позволили прочитать 103 узла, но выявили эти дополнительные случаи; они не считаются успешной итоговой приёмкой.

Исправления: полная bounded-классификация служебного сообщения до обращения к индексу; раздельные транспортная последовательность и ревизия документа; сохранение post-JOIN очереди через finish; последовательная ограниченная live-очередь; ожидание ACK heartbeat; Page.frameNavigated вместо запоздалого tabs.loading для определения смены документа; ожидание освобождения writer перед новым authenticated ready; отдельная stale-подсказка badge. Списки полей ограничены; неизвестный сигнал, поле или изменение узлов не игнорируются.

Автотесты: `npm run check`, `npm test` — 263/263, `git diff --check`. Проверены cold-read, pagination между служебными сообщениями, оба направления presence, запрещённые узлы/неизвестные поля в служебном пакете, очередь вокруг JOIN_END/commit, последовательность ACK, переполнение очереди, гонка delta/heartbeat и задержанное освобождение writer при reconnect. Новых зависимостей нет.

Приватные данные повторных прогонов находятся в `.cache/figma-network/live-ui-fix-20261025/`. Они не добавлены в Git. Реальные изменения макета не выполнялись: открыт View-файл. TODO 15–16 не помечаются полностью выполненными по одной проверке чтения; реальный create/move/delete, неподдержанные операции, Windows и общий RAM-бюджет остаются отдельной приёмкой.
