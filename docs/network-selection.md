# Индекс выбранного поддерева (TODO 09)

Managed snapshot reader удерживает один worker для одного каталога кэша,
манифеста снимка (включая файл, sessionId, generation и хеши частей) и node-id.
Изменение depth, offset, maxNodes или includeHidden использует тот же reader.
Смена selection/снимка освобождает прежний worker до создания следующего.
Legacy captureFile остаётся одноразовым исследовательским адаптером.

В RAM индексируются только прочитанные узлы текущей ветки: Map из ID в JSON,
не более 2048 записей и 4 МиБ учтённых данных. Учёт: два байта на кодовую
единицу JSON и ID плюс 128 байт на запись. Это лимит структуры, не измеренный
RSS процесса. Объекты узлов разбираются временно; результат ограничен прежними
лимитами ответа. Порядок связей, обход и фильтрация видимости остаются общими
для первого и повторного запросов. Узлы сверх RAM-лимита читаются с диска.
Полного долгоживущего индекса документа в RAM нет. Дисковый индекс документа
TODO 08 сохраняется рядом с частями, в decode-*; он нужен для ограниченного
обхода больших веток. Новый запрос не распаковывает и не декодирует документ.

Каждый повторный запрос под read lease проверяет манифест и последовательно
перечитывает части с проверкой хешей. Это сохраняет обнаружение повреждений,
но повторный запрос всё ещё имеет стоимость дискового чтения всего снимка.
Изменение манифеста инвалидирует reader. Одновременные запросы отклоняются
как BUSY, очередь не накапливается.

Очистка/retention через NetworkStore сначала освобождает производный reader.
Отмена, ошибка, таймаут, смена ключа и 60 секунд простоя завершают worker и
удаляют scratch. releaseNetworkSelection() позволяет явно освободить reader.
Worker и idle timer не удерживают Node-процесс. Аварийное завершение процесса
может оставить scratch; восстановление таких каталогов относится к TODO 17.

metrics.selectionCacheHit показывает повторное использование;
loadDecodeIndexMs равен нулю на hit, selectionCache содержит число записей и
учтённый объём. Измерительный стенд различает idle-retained-selection и
idle-after-release. Общий бюджет 500 МБ и Windows здесь не принимаются.

Проверки: смена selection/поколения, повтор с другими параметрами, родительские
связи, порядок, скрытые ветки, повреждение частей, отмена, очистка, большой
выбор с выходом за RAM-лимит. Полный набор: npm run check; npm test.
