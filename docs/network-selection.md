# Индекс выбранного поддерева (TODO 09)

Managed snapshot reader удерживает один worker для одного каталога кэша,
манифеста снимка (включая файл, sessionId, generation и хеши частей) и node-id.
Изменение depth, offset, maxNodes или includeHidden использует тот же reader.
Смена selection/снимка освобождает прежний worker до создания следующего.
Legacy captureFile остаётся одноразовым исследовательским адаптером.

В RAM индексируются только прочитанные узлы текущей ветки: Map из ID в JSON,
не более 2048 записей и 4 МиБ учтённых данных. Учёт: два байта на кодовую
единицу JSON и ID плюс 128 байт на запись. Это лимит структуры, не измеренный
RSS процесса. Объекты узлов разбираются временно; результат ограничен прежними
лимитами ответа. Порядок связей, обход и фильтрация видимости остаются общими
для первого и повторного запросов. Узлы сверх RAM-лимита читаются с диска.
Полного долгоживущего индекса документа в RAM нет. Дисковый индекс документа
TODO 08 сохраняется рядом с частями, в decode-*; он нужен для ограниченного
обхода больших веток. Новый запрос не распаковывает и не декодирует документ.

Каждый повторный запрос под read lease проверяет манифест и последовательно
перечитывает части с проверкой хешей. Это сохраняет обнаружение повреждений,
но повторный запрос всё ещё имеет стоимость дискового чтения всего снимка.
Изменение манифеста инвалидирует reader. Одновременные запросы отклоняются
как BUSY, очередь не накапливается.

Очистка/retention через NetworkStore сначала освобождает производный reader.
Отмена, ошибка, таймаут, смена ключа и 60 секунд простоя завершают worker и
удаляют scratch. releaseNetworkSelection() позволяет явно освободить reader.
Worker и idle timer не удерживают Node-процесс. Аварийное завершение процесса
может оставить scratch; восстановление таких каталогов относится к TODO 17.

metrics.selectionCacheHit показывает повторное использование;
loadDecodeIndexMs равен нулю на hit, selectionCache содержит число записей и
учтённый объём. Измерительный стенд различает idle-retained-selection и
idle-after-release. Общий бюджет 500 МБ и Windows здесь не принимаются.

Проверки: смена selection/поколения, повтор с другими параметрами, родительские
связи, порядок, скрытые ветки, повреждение частей, отмена, очистка, большой
выбор с выходом за RAM-лимит. Полный набор: npm run check; npm test.

## Пагинация и размер ответа (TODO 10)

`get_network_tree` принимает `maxBytes` (4096–150000, по умолчанию 150000):
это предел UTF-8 JSON результата целиком, включая метрики и диагностику,
но без внешней JSON-RPC/MCP-обёртки. `maxNodes` отдельно ограничивает узлы.
Следующий запрос передаёт `traversal.continuation` с тем же источником, URL
selection, depth, includeHidden, maxNodes и maxBytes; offset нужно опустить.
Токен HMAC привязан к манифесту с хешами частей (для legacy — SHA-256 файла),
файлу, узлу и всем параметрам. Изменение снимка/параметров, подделка токена и
перезапуск MCP отклоняют продолжение. Освобождение worker его не инвалидирует.
`nextOffset` и прямой offset оставлены для совместимости исследовательских
скриптов; offset сам по себе не защищает от смены снимка, используйте continuation.

Порядок — preorder с сортировкой wire position. Скрытая ветка пропускается
целиком. Граница depth и скрытые ветки отражаются отдельными счётчиками и
первыми 10 ID; `diagnosticListsTruncated` сообщает сокращение списков.
Исчерпание страниц не означает полноту rendered tree: ограничения исходного
снимка сохраняются; instances раскрываются по правилам и ограничениям `network-layout.md`. Для большей глубины нужен новый
запрос. Узел, который не помещается на страницу, возвращает краткую запись с
`propertiesOmitted`; длинный текст не режется молча. После него обход продолжится.

Проверено: многостраничный обход с Unicode/крупным текстом, отсутствие дублей
и пропусков, точный размер полного JSON, скрытые ветки, граница глубины,
изменение каждого параметра и поколения, подделка токена, повтор после eviction.

## Текущее выделение и screenshot (25 октября 2026)

`get_selection` читает только локальные исходящие `USER_CHANGES.selection`.
Входящее присутствие других пользователей не определяет локальный выбор.
Сохраняются лишь GUID (до 100), без имён пользователей и прочих presence-полей.
Неизвестное выделение возвращает ошибку с предложением выбрать узел заново
или передать URL; только наблюдаемое снятие выделения даёт `nodes: []`.
Имена и типы узлов берутся из сетевого снимка. Смена поколения/отключение
инвалидируют выбор; получение служебного сообщения не меняет document revision.

`source=ui` и UI-обход контекста удалены. `get_network_tree` отсутствует в
обычном MCP; остаётся opt-in внутреннего benchmark service.

Screenshot получает путь предков из сетевого снимка, раскрывает только его
и проверяет точное выделение перед Copy as PNG и чтением результата.
Возвращается изображение выбранного узла, не viewport. Ошибка до запуска
нативного копирования не требует reload; неопределённый результат уже
запущенного копирования сохраняет прежнюю защиту от чужого clipboard.
