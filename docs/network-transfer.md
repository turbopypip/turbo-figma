# Передача захвата через мост (TODO 04)

Используется существующий аутентифицированный WebSocket на loopback. Новых зависимостей и разрешений нет. `extension/connection.js` передаёт выбранный `fileKey` в `auth`; до переподключения менять файл нельзя. Старые клиенты без `fileKey` могут выполнять прежние команды, но не захват.

`src/network-transfer.ts` принимает команды; `extension/network-transfer.js` предоставляет `createCaptureSender(socket, snapshot)` для уже аутентифицированного соединения. В TODO 05 отправитель подключён к `extension/network-collector.js`; см. [описание сборщика](network-collector.md). Сам транспорт проверен синтетическим отправителем через настоящий WebSocket и дисковое хранилище.

## Протокол

Каждая команда — JSON с `type: "capture"`, уникальным `id`, `snapshot: {fileKey, sessionId, generation}` и `action`:

- `begin`: необязательное `format: "ndjson-v1"` обозначает текущий формат (он проверяется и без поля); создать поколение в NetworkStore, дождаться подтверждения.
- `part`: `sequence` от нуля без пропусков и повторов, `data` — канонический base64 непустой части, максимум 262144 декодированных байта. Подтверждение выдаётся после записи и fsync.
- `finish`: `evidence` содержит `schemaReceived`, `joinStarted`, `joinEnded`, `sequenceComplete` (все true), `droppedParts: 0`, `receivedParts` (точное число подтверждённых частей). Подтверждение выдаётся после публикации метаданных.

Ответ `capture-result` повторяет `id`, `snapshot`, `action` и содержит `nextSequence`, `status: "capturing" | "ready"`. Завершение с нулём частей не допускается. Сервер сам проверяет порядок и число сохранённых частей; с TODO 06 сервер независимо проверяет содержимое NDJSON через инспектор начального потока и использует собственные evidence. Подробности: [начальный снимок](network-initial.md). Это не доказательство визуальной полноты дерева Figma.

Ошибка — `capture-error` с коротким `error`, затем закрытие соединения (1008). Клиент не повторяет часть после неопределённого результата: нужно новое соединение и новое поколение. Уже завершённые поколения не перезаписываются. Отмена отправителя также закрывает соединение. Ошибка протокола завершает текущий захват; частичные файлы остаются негодными для чтения и удаляются штатной очисткой.

## Ограничения и жизненный цикл

Окно — одна часть, очередь ожидающих частей — ноль. Вызывающий код обязан дождаться Promise от `begin`, каждой `append` и `finish`. Конкурентный вызов, заполненный WebSocket send buffer или неверное подтверждение завершают захват. Сервер независимо отвергает вторую команду во время дисковой операции. Источник, который нельзя приостановить, должен явно прервать захват при переполнении; этот слой не обещает выдерживать любой темп multiplayer-событий.

Лимит части повторён на обеих сторонах и проверен тестом передачи максимальной части. Общий WebSocket maxPayload остаётся 6 МиБ для совместимости экспорта; протокол захвата накладывает более строгую проверку размера. Base64 и временные копии ограничены одной частью, полного JSON-снимка в отправителе нет. Максимум 10000 частей задаёт хранилище. Это ограничение буферов, не измерение суммарного RAM: бюджет 500000000 байт остаётся непроверенным.

Таймаут по умолчанию — 30 секунд на ожидание команды/записи/подтверждения. Разрыв, таймаут и shutdown отменяют захват; при текущей дисковой операции освобождение слота ждёт её завершения. Зависший системный файловый вызов этим таймаутом принудительно не прерывается. Отмена во время commit проверяется перед публикацией и после неё; при отмене опубликованный manifest убирается до возврата. Завершённый и подтверждённый снимок остаётся на диске после отключения.

Очистка кэша и запросы моста блокируются на время захвата и завершения его отмены. Старое соединение не может писать после передачи владения новому. Новый захват может начаться после освобождения старого writer. Более полный жизненный цикл Figma/worker относится к TODO 15–17.

Проверки: `npm run check`, `npm test`. Тесты покрывают точные байты, границу размера, подтверждения, идентичность файла/сессии/поколения, неверный base64, дубликаты/пропуски, неполные evidence, медленный диск и переполнение с обеих сторон, ошибку диска, таймаут, переподключение и отмену во время завершения. Chrome/Figma и Windows этим набором не проверяются.
