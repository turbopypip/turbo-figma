# TODO 14: вопросы по эффективным значениям и UI-киту

Общее правило: разрешить привязку Figma в значение, затем применить существующие
правила `src/variables.ts`. Имена Figma не используются для выбора CSS-токена.

Уже определено: размеры, отступы, gap, line-height → `--mimir-space-*`;
font-size → `--mimir-size-text-*`; font-weight → `--mimir-font-weight-text-*`;
font-family → `--mimir-font-inter` / `--mimir-font-montserrat`;
радиусы → `--mimir-control-(input-)?radius*`; border-width →
`--mimir-control-border-width`. Нецветовой кандидат должен быть единственным.
Для цвета действует прежний выбор первого точного литерала, кроме gos-znak и aliases.

Вопросы для последующего уточнения:

- Для opacity, letter-spacing, paragraph-spacing/indent и прочих категорий нет
  правила выбора семейства UI-kit. Эффективное значение сохраняется; CSS, если
  его преобразование поддержано, остаётся литералом с `unsupported` в matching.
  Не выбираем случайный токен только по совпадению числа.
- LINE_HEIGHT / LETTER_SPACING: привязка применяется при явно сохранённых PIXELS.
  Для процентов и отсутствующих единиц значение не выдаётся за пиксели;
  нужна проверка wire-семантики. Такие привязки отмечаются unresolved.
- Неизвестный variableField/nodeField, выражения и недоступные определения/режимы
  остаются явными unresolved. Это не обещание покрытия всех полей Figma.
- Эффекты и обводки сохраняют эффективные параметры; построение CSS сложных
  теней/обводок по-прежнему требует отдельной проверки геометрии (TODO 19).
- Новые нецветовые сценарии проверены синтетически и через дисковый reader;
  свежая полная сверка этих сценариев с живым Figma-инспектором не выполнена.
