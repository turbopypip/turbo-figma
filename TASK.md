# Figma MCP для Kilo Code

## Цель

Создать полностью бесплатный инструмент, предоставляющий агенту Kilo Code доступ к данным Figma через MCP для вёрстки в существующем проекте. Основной сценарий — чтение оригинального файла, к которому у пользователя есть только права просмотра.

## Обязательные требования: бесплатно и без прав редактирования

Зафиксировано по уточнению пользователя от 19 октября 2026 года. Эти требования имеют приоритет над ранее выбранной архитектурой и существующей реализацией.

**Пользователь должен получить БЕСПЛАТНЫЙ инструмент на всех уровнях, чтобы предоставить агенту MCP-доступ к Figma.**

- Вся обязательная цепочка установки, подключения и использования должна работать без оплаты: Figma, доступ к макету, плагин или другой адаптер, MCP-сервер, зависимости и необходимые сервисы.
- Не требовать платную подписку Figma, Dev/Full seat, платный Dev Mode, платный плагин, API, посредник, хостинг или обязательный платный тариф агента/модели. Платная модель, добровольно выбранная пользователем, не должна становиться технической зависимостью инструмента; для приёмки нужен воспроизводимый бесплатный сценарий.
- Пробный период, временные бонусные кредиты или уже оплаченная кем-либо подписка не считаются выполнением требования бесплатности.
- Работать с **оригинальным файлом**, доступным пользователю **только на просмотр**, без запроса прав редактирования и без изменения документа.
- Копия в Drafts, ручной экспорт владельцем или запуск плагина владельцем не заменяют основной сценарий и не считаются выполнением задачи.
- Пользователь входит в нужный аккаунт Figma обычным способом. Не использовать Figma REST API и REST-токены; не зависеть от квот REST API.
- Допустимы технические ограничения размера данных, экспорта и параллелизма для экономии ресурсов; они должны быть явными. Платных квот и обязательных покупок для продолжения работы быть не должно.
- Не обходить права доступа и ограничения владельца: предоставлять только данные, доступные пользователю в его аккаунте.
- Способ подключения выбирать по этим требованиям. Наличие уже написанного плагина не является основанием требовать оплату или права редактирования.

### Статус существующего решения

Прежний прототип MCP + Figma Plugin API **не принят как решение основного сценария и удалён**. Вариант Design предполагает возможность запуска плагина в файле, а вариант Dev Mode зависит от доступа к Dev Mode plugins. Добавление `inspect` само по себе не обеспечивает бесплатную работу с обычными правами View. Успешные автоматические тесты прототипа не подтверждают выполнение этого бизнес-требования.

### Обязательная приёмка

На реальном файле, доступном только для просмотра, показать получение контекста, изображения и необходимых ассетов через MCP в Kilo Code без редактирования, копирования файла, действий владельца и платных функций. Зафиксировать аккаунт/тариф и права без раскрытия секретов, используемые компоненты и отсутствие обязательных расходов по всей цепочке. Если какая-либо часть сценария недоступна, прямо отметить невыполнение требования, а не подменять его платным или редакторским вариантом.

## Требование к ресурсам

**Решение должно потреблять минимальное количество ресурсов ПК на Windows.**

Это основной критерий выбора среди решений, удовлетворяющих обязательным требованиям бесплатности и доступа только на просмотр. При равной функциональности выбирать вариант с меньшим потреблением RAM, CPU, диска и меньшим числом фоновых процессов. Удобство разработки не должно оправдывать тяжёлую инфраструктуру.

- Основная платформа — Windows 10/11 x64, без обязательных WSL, Docker и прав администратора.
- Не запускать отдельный браузер, Electron-приложение, локальную LLM, базу данных или постоянно работающую службу.
- Один процесс MCP-сервера; локальное соединение с расширением обслуживается этим же процессом.
- Не выполнять постоянный опрос Figma, сканирование проекта или обработку всего документа в фоне.
- Читать и преобразовывать данные по запросу агента. События соединения и выделения обрабатывать без дорогостоящего пересчёта дерева.
- Экспортировать изображения только по запросу, с ограничением разрешения и размера результата.
- Ограничить объём кеша, размер сообщений и число одновременных тяжёлых операций. Освобождать временные данные после завершения запроса или отключения.
- Использовать минимальный набор зависимостей. Для работы установленного сервера не нужны сборщик, TypeScript watch и другие процессы разработки.
- Завершать сервер и освобождать соединения при закрытии MCP-сессии Kilo Code.

### Проверка потребления ресурсов

Приведённые ниже числа — начальные инженерные ориентиры, а не уже измеренные показатели. Их нужно проверить на Windows и уточнить по результатам прототипа, сохраняя минимальное потребление ресурсов главным требованием.

- Простой: средняя загрузка CPU процессом сервера не более 1% за 60 секунд, память процесса ориентировочно до 100 МиБ.
- После серии запросов потребление памяти стабилизируется; отсутствуют непрерывный рост памяти и накопление временных файлов.
- В простое отсутствуют периодические запросы к Figma и вычисления по макету.
- Для чтения структуры и экспорта изображений измерять время, пиковую память и CPU отдельно; фиксировать размер тестового фрейма и параметры изображения.
- Указывать конфигурацию ПК, версию Windows и Node.js, способ измерения. Отдельно учитывать сервер и дополнительную нагрузку расширения на Chrome; базовое потребление Figma и Kilo Code не включать в бюджет сервера.
- Большие запросы должны ограничиваться или завершаться понятной ошибкой, а не приводить к зависанию ПК.

## Архитектура после переработки

Уточнение направления от 25 октября 2026: пользователь согласовал переход получения дерева и свойств с UI-обхода на анализ сетевого обмена. Требования конкретной фичи записаны в локальном `ideas/BT-network-selection.md` (папка `ideas/` исключена из Git): быстрый контекст выбранного слоя, не более 500 МБ суммарной RAM с пиками, постоянный индекс только выбранного поддерева, единый очищаемый кэш `.cache/figma-network/` внутри клонированного репозитория. DOM-only описание ниже отражает предыдущую архитектуру и не запрещает реализацию согласованного сетевого адаптера. Сам сетевой прототип пока не подтверждает выполнение всех критериев приёмки.

По прямому указанию пользователя вариант с Figma-плагином удалён и не поддерживается. Единственный адаптер — расширение Chrome, работающее с DOM и штатными командами копирования открытого файла. Kilo CLI подключается по stdio к одному локальному MCP-процессу, расширение — по WebSocket с секретом.

Секрет вводится на странице расширения, не передаётся странице Figma или модели. Расширение привязано к явно выбранной вкладке и файлу. Оно не использует приватный runtime Figma, REST API, cookies или отдельный браузер. В простое опроса нет. Контекст DOM неполон: скрытые/виртуализированные строки и непоказанные свойства явно обозначаются как недоступные. Экспорт использует Copy as PNG/SVG и заменяет буфер обмена. Реальный экспорт, бесплатность всей цепочки и Windows-производительность подлежат приёмке.

## Основной пользовательский сценарий

1. Пользователь устанавливает сервер и подключает его в Kilo Code.
2. Входит в свой аккаунт Figma и открывает оригинальный макет с правами только на просмотр. Подключает бесплатный адаптер и выбирает нужный фрейм без перехода на платный тариф.
3. Просит Kilo Code сверстать выделенный экран с использованием компонентов текущего проекта.
4. Агент получает структуру, визуальный образец и необходимые ассеты через MCP.
5. После изменения макета агент может повторно запросить актуальные данные.

## Инструменты первой версии

| Инструмент | Назначение |
| --- | --- |
| `get_selection` | Вернуть идентификаторы, типы и названия выделенных узлов без полного дерева документа. |
| `get_design_context` | Вернуть компактное структурированное описание выбранного узла или узла по ID. |
| `get_screenshot` | Экспортировать PNG выбранного фрейма с ограничением масштаба и размера. |
| `export_assets` | Экспортировать запрошенные иконки и изображения в разрешённую локальную папку. |

Для больших деревьев предусмотреть ограничение глубины и количества узлов, явный признак сокращения результата и возможность отдельно запросить дочерний узел. Не выдавать неполные данные за полный макет.

## Данные для вёрстки

- Идентификаторы, типы, названия, иерархия и видимость элементов.
- Размеры, координаты и правила изменения размеров.
- Auto Layout: направление, gap, padding, выравнивание, переносы и режимы размеров, если доступны.
- Текст и стили отдельных диапазонов: шрифт, размер, начертание, межстрочное и межбуквенное расстояние.
- Заливки, обводки, скругления, прозрачность и эффекты.
- Компоненты, экземпляры, варианты и свойства в пределах доступных данных интерфейса Properties.
- Доступные привязки стилей и переменных; недоступные значения обозначать явно.
- Ссылки между элементами и экспортированными ассетами.

Сохранять значимые для внешнего вида сведения, убирая технический шум и повторы. Не выдумывать адаптивные правила, поведение интерфейса и соответствия компонентам проекта, которых нет в исходных данных.

## Локальность и безопасность

- Сервер слушает только loopback-интерфейс, а не всю локальную сеть.
- Соединение расширения с сервером защищено проверкой сессионного секрета или эквивалентным механизмом; одного CORS недостаточно.
- Расширение запрашивает только необходимые сетевые разрешения.
- Сервер и расширение не отправляют макет сторонним сервисам и не содержат телеметрии. Данные, переданные Kilo Code, далее обрабатываются согласно настройкам выбранной пользователем модели.
- Запись ассетов ограничена явно настроенной папкой. Защита от выхода за её пределы, коллизий имён и неявной перезаписи файлов.
- Первая версия только читает макет и экспортирует данные; не изменяет документ Figma.

## Надёжность и совместимость

- Обрабатывать отсутствие выделения, закрытие расширения, удалённый узел, недоступные свойства, обрыв соединения и конфликт локального порта.
- У запросов есть таймауты; отмена запроса освобождает связанные ресурсы, насколько это позволяет нативное копирование Figma.
- Повторное подключение не создаёт дублирующих процессов, обработчиков или очередей.
- Работать с путями Windows, включая пробелы и кириллицу.
- Документировать минимальную поддерживаемую версию Node.js и проверенную версию Kilo Code; пример конфигурации должен соответствовать этой версии.
- Кеш, если используется, имеет предел размера и механизм обновления после изменений макета. Не возвращать устаревшие данные как актуальные.

## Результат первой версии

- Исходники расширения Chrome и MCP-сервера.
- Команды установки, сборки и запуска на Windows.
- Пример настройки MCP в Kilo Code без секретов в репозитории.
- Инструкция по загрузке расширения и прохождению основного сценария.
- Проверка получения контекста, PNG и ассетов через Kilo Code на реальном фрейме.
- Проверка отключения, повторного подключения, ограничений больших запросов и безопасной записи файлов.
- Краткий отчёт об измеренном потреблении ресурсов на Windows в простое и под нагрузкой.

## За пределами первой версии

- Парсинг внутреннего формата `.fig`. Ранее исключённое исследование DOM/браузерного адаптера допускается при пересмотре архитектуры, если оно необходимо для бесплатного сценария с правами просмотра; его пригодность ещё не подтверждена.
- Собственный редактор, отдельный графический интерфейс сервера и облачный сервис.
- Автоматическое изменение макета, фоновая синхронизация всего документа и индексация всех файлов проекта.
- Гарантия автоматической вёрстки без ошибок: качество реализации зависит от агента, модели, структуры макета и требований проекта.

## Уточнения кэша и зависимостей (25 октября 2026)

- Очистка — отдельная кнопка в окне расширения; через существующий аутентифицированный мост. Кэш не зависит от cwd Kilo.
- Данные фрейма различаются по `fileKey + pageId + frameId`, версия — по сессии и поколению. Общий сетевой снимок не дублируется на каждый фрейм.
- Новые зависимости проекта обязательно согласовывать с пользователем до добавления. Другой язык допустим при обоснованной необходимости, но не требуется для кэша.
