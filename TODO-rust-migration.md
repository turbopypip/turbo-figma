# TODO: переход Figma MCP на Rust

Дата: 25 октября 2026. База: версия 0.3.0, commit `fc3aaea`.

Цель: снизить время ответа и расход оперативной памяти, последовательно заменяя подходящие участки Node.js реализациями на Rust. Для каждого участка сначала делаем совместимый прототип и сравнительные тесты, затем решаем, включать ли его в продукт. Если перенос не оправдан, сохраняем Node.js и документируем решение.

Подробные требования, методика и таблицы результатов: [RUST-MIGRATION.md](RUST-MIGRATION.md). Этот файл — список исполняемых задач; документ сравнения — место для чисел и обоснований. Он сейчас хранится локально и исключён из Git, поэтому при передаче списка другому разработчику нужно передать оба файла.

## Правила выполнения

- Выполнять пункты по порядку. Перед каждым пунктом уточнять конкретный объём реализации и проверки; слишком большой пункт предварительно разбить на подпункты.
- Каждый пункт включает реализацию или исследование, самостоятельное review, подходящие тесты, исправления и запись результата. Галочка означает выполненные критерии, а не только написанный код.
- Rust переносит существующее поведение: публичный MCP, порядок узлов, layout/styles/instances/variables, ограничения, continuation, freshness, отмену и ошибки. Упрощённый результат не считается ускорением.
- Общий пик дополнительной RAM: **не более 500 000 000 байт** для MCP, декодера, индексов, буферов, дочерних процессов и дополнительной памяти расширения. Worker RSS повторно не суммировать. Базовая память Figma/браузера и Kilo исключается; неполное покрытие измерений отмечать явно.
- Сохранять ограниченный selection-кэш, дисковый индекс, одну тяжёлую операцию, ограниченные очереди и освобождение ресурсов. Снимки и временные данные — в `.cache/figma-network/`.
- Сравнивать N0 (зафиксированный текущий Node.js), N1 (сопоставимая оптимизация Node.js, если нужна) и Rust на одинаковых данных и условиях. Архитектурную оптимизацию не приписывать языку.
- До теста задавать минимальный полезный выигрыш времени/памяти и допустимую регрессию второй метрики. После теста заполнять соответствующую таблицу R01–R10 и фиксировать решение: переносить / оставить Node.js / отложить.
- Новые зависимости согласовывать до добавления согласно требованиям проекта. Целевые платформы — macOS и Windows, без обязательных WSL/Docker и отдельной постоянной службы.
- Создание этого списка не запускает миграцию. Существующий Node.js-путь сохранять доступным до приёмки заменяющего участка.
