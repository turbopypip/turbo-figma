## Как работаем

- Решаем по одному пункту в указанном порядке. Перед реализацией — короткий план конкретного TODO и согласование с пользователем (`PLAN_MODE=per_todo`).
- Каждый пункт проходит реализацию, самостоятельный code review и подходящие проверки. При проблемах — исправление, повторное review и проверки.
- Только после этого ставим `[x]`, записываем результат и переходим к обсуждению следующего пункта. Создание списка не означает разрешения выполнить всё сразу.
- Если пункт окажется слишком большим, сначала дробим его здесь на подпункты с собственными критериями готовности.
- Статусы и доказательства храним здесь; сырые данные Figma и секреты в Git не добавляем.

## Исходная точка

Существует экспериментальный сборщик `experiments/figma-network-probe/` и MCP-инструмент `get_network_tree`, читающий вручную сохранённый JSON. Декодирование fig-wire/Kiwi проверено на реальном снимке: 45 440 записей документа, 118 записей выбранной ветки. Каждый запрос заново строит модель в отдельном worker. Основной `get_design_context` всё ещё использует UI.

На момент составления списка: `npm run check` и 59/59 тестов проходят. Прошлый пик 339 МиБ относится к процессу декодирования, не ко всей реализации. Он не доказывает выполнение лимита RAM.

## Ограничения для всех пунктов

- Максимум **500 000 000 байт RAM суммарно с пиками**: MCP, декодер, индексы, буферы и дополнительная память расширения. Базовая память браузера/Figma и Kilo исключается. Ограничение V8 heap не заменяет измерение RAM.
- В долгоживущей RAM — только выбранное поддерево; нет полного индекса файла и коллекции прежних selection. Одна тяжёлая операция одновременно.
- Все новые снимки, промежуточные файлы и технические дампы — в `.cache/figma-network/` внутри клонированного репозитория. Старые исследовательские файлы автоматически не удаляем.
- Все новые зависимости согласовываем с пользователем до добавления.
- Бесплатно, оригинальный файл с правами View, существующий браузер, без REST API, платного Dev Mode, WSL/Docker и отдельной службы.
- Неполноту и устаревание показываем явно. Никакого незаметного возврата к дорогому UI-обходу.
- PNG/SVG остаются отдельным механизмом; их сетевую замену этот список не обещает. Rust не является обязательной частью плана.
