# turbo-figma

Локальный MCP-сервер на Rust читает дизайн из сетевого захвата Figma. Расширение Chrome подключает выбранную вкладку, передаёт захват и выполняет PNG/SVG-операции через интерфейс Figma. Node.js нужен для установки и тестовых утилит; сервер работает отдельным Rust-бинарником.

## Установка

Для сборки нужны Rust/Cargo и C/C++ toolchain (Zstandard собирается из исходников). В CI и Windows-установщике закреплён Rust 1.99.1. Для npm-утилит нужен Node.js 20.12+; CI использует Node.js 22. Расширению нужен Chromium 125+ с поддержкой Chrome debugger API.

### Windows 10/11 x64

Из каталога репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Assets 'C:\Projects\site\public\figma'
```

Скрипт устанавливает недостающие зависимости через winget, готовит MSVC/Windows SDK, собирает Rust и создаёт локальную конфигурацию. Для готового окружения добавь `-SkipDependencies`. Установка C++ Build Tools может потребовать права администратора. Скрипт не запускает тесты и не редактирует конфигурацию Kilo.

### macOS / Linux

Подготовь Rust toolchain и системный C/C++ compiler (на macOS — Xcode Command Line Tools), затем:

```sh
npm ci
npm run build
npm run setup -- --assets /absolute/path/to/project/public/figma
```

`npm run build` собирает release-бинарник `target/release/turbo-figma` (`.exe` на Windows). `npm run build:rust` — синоним. Сборка использует Cargo.lock. При наличии локального toolchain в `.local/cargo` скрипт использует его.

Linux включён в CI-матрицу; реальная браузерная приёмка на конкретной ОС остаётся отдельной проверкой.

## Подключение

1. Объедини созданный `.local/kilo.json` со своей конфигурацией Kilo. В нём абсолютный путь к Rust-бинарнику, аргументы `--server`, путь к конфигурации и каталог проекта. Пример формы — [examples/kilo.json](examples/kilo.json).
2. Открой `chrome://extensions`, включи режим разработчика и загрузи каталог `extension/` как распакованное расширение. В Яндекс Браузере используй страницу расширений и загрузку распакованного расширения, если она доступна в установленной версии.
3. Запусти MCP через Kilo. Открой нужный файл Figma и нажми значок расширения. Укажи порт и секрет из `.local/pairing.txt`. Ключ сохраняется в браузере; для другой вкладки выбери «Подключить» в ней.
4. Запусти сетевой захват через панель расширения. Для уже открытого файла используй захват с перезагрузкой, чтобы получить начальную схему и полный снимок. Дождись готовности захвата.
5. Передай агенту ссылку на узел Figma. Для `get_design_context` ручное выделение узла не требуется.

При обновлении пересобери сервер и повтори `npm run setup -- --assets <прежний абсолютный каталог>`. Замени старую запись MCP в Kilo на созданную `turbo-figma`: бинарник теперь находится в `target/release/turbo-figma`, прежний путь `rust/helper/target/release/figma-rust-helper` больше не используется. Ключ подключения и config сохраняются. После обновления расширения перезагрузи его на странице расширений и подключи вкладку заново. Старые маркеры владельца кэша распознаются, новые захваты маркируются `turbo-figma`.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `get_connection_status` | Состояние соединения с расширением; подключение не гарантирует готовность захвата или экспорта. |
| `get_selection` | Выделение из наблюдаемого сетевого состояния. |
| `get_design_context` | Дерево, layout, стили, текст, компоненты, переменные и диагностика доступных данных. |
| `get_screenshot` | PNG выбранного узла через Figma; требует доступного узла и фокуса вкладки. |
| `export_assets` | PNG/SVG в настроенный каталог ассетов. |

Контекст читается только из сетевого снимка. Устаревшего обхода Layers/Properties для получения контекста нет. Непустой `traversal.continuation` означает, что нужно запросить следующую страницу с теми же параметрами. `depth`, скрытые слои и предупреждения о неразрешённых данных влияют на полноту независимо от пагинации. Изменение снимка или его revision делает прежний continuation недействительным.

Скриншоты и экспорт активируют вкладку и могут заменить буфер обмена. Наличие узла в снимке не гарантирует его доступность в смонтированном дереве Layers. MCP использует права текущего пользователя Figma; сетевые данные и извлечение отдельных свойств зависят от внутреннего протокола Figma.

## Конфигурация

`setup` создаёт `.local/config.json`, `.local/pairing.txt` и `.local/kilo.json`. Эти файлы содержат локальные пути и секрет подключения и не должны попадать в Git. Повторный setup сохраняет ключ; смена каталога ассетов требует явного редактирования config.

Поля config:

- `secret` — ключ подключения, создаётся автоматически;
- `port` — порт WebSocket на `127.0.0.1`, по умолчанию `3055`;
- `assetDirectory` — абсолютный путь вне управляемого кэша;
- `adapter` — `browser`, если указан;
- `variablesFile` — необязательный путь к файлу CSS-переменных UI-кита; рекомендуется абсолютный.

UI-kit файл должен содержать плоские блоки `:root` с custom properties, до 2 МиБ. Простые алиасы `var(--name)` поддерживаются; Sass, импорты, вложенность и вычисления не исполняются. Совпадения переменных и неоднозначности возвращаются в контексте; без файла выдаются обычные значения.

Для диагностики можно выполнить `npm start`: это тонкий запускатель того же Rust-бинарника. `TURBO_FIGMA_BINARY` переопределяет путь бинарника в утилитах, `TURBO_FIGMA_CONFIG` — config для `npm start`. Сгенерированная команда Kilo использует явные аргументы. Не запускай два сервера на одном порту.

## Восстановление и кэш

- `connected: true` относится к мосту. После потери наблюдения `STALE` требует нового захвата, даже если WebSocket уже восстановился.
- При `STALE` проверь состояние расширения, переподключи вкладку при необходимости и запусти новый захват с перезагрузкой. Начни чтение без старого continuation.
- При `Node not found among expanded Layers` открой нужную страницу и сделай узел доступным в Layers перед повторным экспортом.
- При `Previous native copy did not finish reliably` дождись завершения текущего запроса, перезагрузи Figma и подключись снова. Автоматическое восстановление экспорта пока ограничено.
- Код закрытия `1008` сам по себе не определяет причину: возможны отказ авторизации, второе подключение и ошибка захвата. Проверь `captureError`, `lastDisconnect` и stderr сервера. Некоторые причины пока теряются.

Снимки и временные индексы находятся в `.cache/figma-network` относительно каталога проекта, переданного серверу. Кнопки состояния и очистки кэша доступны в расширении; активные данные защищены от удаления. Кэш может содержать данные макета. Разрешение `debugger` нужно для сетевого захвата выбранной вкладки; остановить его можно в панели расширения.

## Разработка и проверки

```sh
npm ci
npm run check
npm test
```

`check` проверяет синтаксис JavaScript и выполняет Cargo check. `test` собирает Rust, запускает Rust unit tests и JavaScript-тесты расширения, MCP-клиента и Rust-процесса. Тесты требуют бинарник; стенд использует синтетические сетевые записи и не заменяет живую проверку Figma/Kilo. Эталон `tests/fixtures/traversal.json` зафиксирован перед удалением Node-реализации после успешного сравнения с Rust; он проверяет instances, геометрию, переменные и пагинацию без второго сервера.

Структура проекта:

- `src/` — Rust-сервер, сгруппированный по назначению: `capture/`, `decoder/`, `context/`, `storage/` и `diagnostics/`;
- `resources/` — контракт инструментов и список сетевых полей;
- `extension/` — браузерный мост, захват и UI-операции;
- `scripts/` — сборка, setup, запуск и проверка журнала пагинации Kilo;
- `tests/` — проверки браузерной части и Rust через клиентские протоколы.

Диагностические CLI-команды отделены от серверного запуска: `--diagnostics`, `--inspect-input`, `--decode`, `--inspect-index`. Обычный запуск — `turbo-figma --server <config.json> <project-directory>`.

### Восстановление после разрыва связи

Переподключение восстанавливает мост, но не актуальность прежнего снимка. После reconnect, перезапуска MCP или service worker нажми **«Перезагрузить и захватить»** и дождись готовности. Расширение подсказывает это действие; вкладка автоматически не перезагружается. Чтение начни заново: continuation от прежнего наблюдения недействителен.

`get_connection_status` отдельно возвращает `readReady` (готовность начать чтение), `snapshotState` (`capture_required`, `capturing`, `ready`) и `nextAction` (`connect`, `wait`, `reload_and_capture`, `read`). Готовность относится к снимку подключённого файла и не гарантирует наличие selection или возможность экспорта. Статус отражает момент проверки.
