# Figma MCP для Kilo CLI — Chrome и Яндекс Браузер

**Целевой клиент — Kilo CLI в терминале (в том числе на Windows), не расширение Kilo для VS Code.** Настройка MCP, инструкции запуска и индикатор подключения в этом проекте относятся к терминальному Kilo CLI.

Расширение для Chrome и Яндекс Браузера читает открытый оригинальный файл Figma через сетевой захват, а для выделения и экспорта — через доступный пользователю интерфейс, и передаёт данные локальному MCP-серверу. Вход выполняется обычным способом в выбранном браузере. Figma Desktop, Figma-плагин, Dev Mode и REST API не используются. Сервер не запускает браузер и не получает cookies или токены Figma.

**Статус: экспериментальный браузерный адаптер.** На macOS в реальном файле с правами View проверены все четыре MCP-инструмента, PNG/SVG-экспорт и подключение Kilo CLI. Обход баннера прочитал 128 уникальных узлов за 24,2 секунды и два запроса после раскрытия предков. Windows и выполнение задачи самой моделью пока не проверены. Подробные результаты и ограничения — в [TEST_REPORT.md](TEST_REPORT.md).

## Установка

Нужны настольный Chrome или Яндекс Браузер, Node.js 20.12+ и установленный Kilo CLI. Команды выполняй из папки этого репозитория. Проверено на macOS; Windows 10/11 остаётся целевой, но пока не проверенной платформой.

```powershell
npm ci
npm run check
npm test
npm run setup -- --assets "C:\Users\User\Проект\public\figma"
```

На macOS/Linux вместо последней команды используй свою абсолютную папку экспорта, например:

```sh
npm run setup -- --assets "/Users/your-name/projects/site/public/figma"
```

`npm test` также собирает сервер в `dist/`; для сборки без тестов есть `npm run build`.

Укажи свою абсолютную папку экспорта. Setup создаёт `.local/config.json`, `.local/pairing.txt` и `.local/kilo.json`. Повторный запуск сохраняет секрет и переводит старую настройку на браузерный адаптер. Изменение папки экспорта требует явного редактирования config.json.

Если используешь UI-кит, добавь в созданный `.local/config.json` поле `variablesFile` с абсолютным путём к его `variables.scss`, сохранив остальные поля. Например: `"variablesFile": "C:/Projects/ui-kit/src/assets/styles/variables.scss"`. Это отдельная настройка от `--assets`: assets задаёт папку выгрузки изображений, variablesFile — файл для подстановки CSS-переменных. [Подробности и Windows-пути](#автоматическая-подстановка-переменных-ui-кита).

Объедини поле `mcp.figma` из `.local/kilo.json` с настройками проекта Kilo (`kilo.jsonc` или `.kilo/kilo.jsonc`), сохранив остальные настройки. Пример: [`examples/kilo.json`](examples/kilo.json).

```powershell
kilo mcp list
```

`figma connected` означает соединение Kilo с MCP-сервером. После проверки открой рабочую сессию Kilo: соединение с браузером нужно устанавливать, пока сервер запущен клиентом. Одновременно запускай только одну сессию для одного порта.

В терминале перейди в проект, где будешь верстать сайт и куда добавлена настройка `mcp.figma`, затем запусти рабочую сессию:

```sh
kilo
```

Оставь её запущенной и подключи выбранный браузер по инструкции ниже. Отдельный `npm start` не нужен: MCP-сервер запускает Kilo.

## Установка расширения: Chrome и Яндекс Браузер

Для обоих браузеров используется одна и та же папка `extension` с Manifest V3. Собирать расширение, менять `chrome.*` в коде или создавать отдельный манифест для Яндекса не нужно. Если скачал проект ZIP-архивом, сначала распакуй его. Выбирай папку `extension`, внутри которой лежит `manifest.json`, а не корень репозитория.

| Шаг | Google Chrome | Яндекс Браузер |
| --- | --- | --- |
| Страница установки | `chrome://extensions` | `browser://extensions` |
| Режим установки | Включить **Режим разработчика / Developer mode** | Включить **Режим разработчика** |
| Загрузка | **Загрузить распакованное расширение / Load unpacked** → папка `extension` | **Загрузить распакованное расширение** → та же папка `extension` |
| После изменения файлов | Нажать кнопку обновления на карточке расширения | Нажать кнопку обновления на карточке расширения |

### Подключение Chrome

1. Открой `chrome://extensions` и загрузи расширение по таблице выше.
2. Найди **Figma Kilo Browser Bridge** в меню расширений и закрепи значок для удобства.
3. Перейди к общим шагам подключения ниже.

### Подключение Яндекс Браузера

1. В адресной строке открой именно `browser://extensions` и загрузи расширение по таблице выше.
2. Убедись, что **Figma Kilo Browser Bridge** включено. Если значок скрыт, открой меню расширений и включи его отображение на панели.
3. Перейди к общим шагам подключения ниже. При переходе из Chrome введи секрет заново: у каждого браузера отдельное локальное хранилище. Сначала отключи мост в Chrome — один MCP-сервер принимает только одно подключение расширения.

Если браузер сообщает о слишком старой версии, обнови его. Поле `minimum_chrome_version: 125` относится к версии движка Chromium, а не к номеру Яндекс Браузера вида `26.x`; удалять это ограничение не нужно. Для дочерних worker-сессий сетевого захвата нужен Chromium 125+ ([debugger API](https://developer.chrome.com/docs/extensions/reference/api/debugger)). Начиная с Chromium 116 обмен по WebSocket поддерживает фоновый процесс активным ([документация Chrome](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle#chrome-116)).

Если расширение отключилось, проверь его состояние на `browser://extensions`. Яндекс может отключать расширения из непроверенных источников, а корпоративные политики могут ограничивать установку; см. [справку Яндекса](https://www.yandex.ru/support/browser/ru/personalization/extension).

**Проверка совместимости, 22 октября 2026:** в Яндекс Браузере 26.8.3.1016 (Chromium 150) на macOS, в отдельном тестовом профиле в headless-режиме, исходное расширение загрузилось без патча. Проверены запуск фонового service worker, панель и её обмен сообщениями с фоном, чтение/запись `storage.session`, авторизация по WebSocket на локальном сервере. Полный сценарий с авторизованным макетом Figma, доступом по `activeTab` и PNG/SVG-экспортом в Яндексе пока не проверен. Мобильные браузеры не входят в этот сценарий установки.

## Подключение к Kilo — общие шаги

1. В выбранном браузере войди в Figma и открой нужный оригинальный файл с правами View. Интерфейс Figma должен быть на английском.
2. На этой вкладке нажми значок **Figma Kilo Browser Bridge**. Откроется небольшая панель со статусом и полем секрета для выбранной вкладки.
3. Вставь только значение `Secret` из `.local/pairing.txt`, укажи порт из того же файла и нажми «Подключить». Не отправляй секрет модели. После успешного подключения ключ и порт сохраняются локально в профиле браузера (`chrome.storage.local`), без синхронизации и передачи в URL. Повторно вводить ключ не нужно: вместо поля отображается «Секрет сохранён» и кнопка «Ввести новый секрет». Если ключа нет или нажата кнопка «Забыть ключ», поле ввода показывается сразу.
4. Нажми **«Перезагрузить и захватить»** и дождись сохранения снимка с включённым наблюдением. Панель можно закрыть — соединение работает в фоне. Дай агенту ссылку **Copy link to selection** из этого файла. Либо выбери слой вручную.
5. В Kilo попроси: «Сверстай баннер по этой ссылке: <selection URL>. Вызови get_design_context с url, затем get_screenshot. Используй nodes[].layout.css и свойства каждого слоя; продолжай страницы через traversal.continuation, учитывай freshness и layout.unresolved. Не выдумывай отсутствующие значения».

При следующем запуске: открой рабочую сессию Kilo → нужный файл Figma в выбранном браузере → значок расширения → «Подключить» с сохранённым ключом. Секрет остаётся тем же, пока не изменена локальная конфигурация.

Если подключение не устанавливается, проверь, что сессия Kilo работает, порт совпадает с `Endpoint` в `.local/pairing.txt` (по умолчанию `3055`), а другой Kilo или тестовый сервер не занимает этот порт. Команда `kilo mcp list` проверяет MCP, но не держит его запущенным для дальнейшей работы. После обновления файлов расширения нажми «Обновить» у расширения на `chrome://extensions` (Chrome) или `browser://extensions` (Яндекс), заново открой подключение его значком на вкладке Figma — сохранённый ключ загрузится автоматически.

Разрешения расширения: `activeTab`, `scripting`, `clipboardRead`, `clipboardWrite`, `storage`, `alarms`, `debugger`. Доступ к DOM даётся нажатием значка на выбранной вкладке; нет постоянного разрешения на все сайты, cookies, историю или загрузки. Секрет хранится локально в профиле расширения и в памяти фонового процесса расширения. Кнопка «Забыть ключ» удаляет сохранённые ключ и порт.

**Экспорт активирует вкладку Figma; PNG заменяет буфер обмена.** Для PNG адаптер сначала записывает свой маркер, затем вызывает штатное Copy as PNG и читает результат. SVG получается через панель Export: временно перехватывается только загрузка blob SVG/ZIP, а ZIP с единственной SVG распаковывается в памяти. Настройки экспорта должны содержать одну строку; адаптер выбирает SVG. Предыдущее содержимое буфера не читается и не восстанавливается. Пока идёт экспорт, не меняй выделение, фокус и содержимое буфера: источник одновременно скопированного пользователем изображения невозможно достоверно отличить от результата Figma.

После незавершённого копирования PNG перезагрузи вкладку Figma: нативное копирование нельзя принудительно отменить. Закрытие маленькой панели не отключает мост. В простое нет чтения макета: раз в 20 секунд передаётся служебный ping для поддержания фонового соединения. При обрыве связи расширение повторяет подключение с задержкой от 1 до 30 секунд; после приостановки фонового процесса таймер браузера пробуждает его примерно раз в минуту. Запросы и экспорты не повторяются. «Отключить» останавливает повторы, сохраняя ключ; «Забыть ключ» удаляет его. Отказ авторизации останавливает повторы. Закрытие выбранной вкладки или переход на другой файл отключает мост. После перезапуска браузера выбери макет и нажми «Подключить».

## Экспериментальный сетевой захват

После подключения к MCP на той же вкладке нажми **«Начать сетевой захват»**. Требуется разрешение `debugger`; Chrome покажет панель отладки. Сборщик сохраняет только входящие multiplayer-сообщения выбранного файла, включая дочерние worker, частями в `.cache/figma-network/`. HTTP-тела, шрифты и исходящие сообщения не сохраняются. Полный JSON не накапливается в RAM или storage расширения.

Для полного начального снимка используй отдельную кнопку **«Перезагрузить и захватить»**: выбранная подключённая вкладка Figma будет перезагружена после включения перехвата. Обычный запуск не перезагружает вкладку и может пропустить начало потока. MCP проверяет схему, JOIN_START и JOIN_END и автоматически сохраняет готовый снимок на диск без ручного скачивания. Статус «готов» появляется только после подтверждения записи; debugger остаётся подключённым для наблюдения. Поддержанное входящее изменение применяется к подготовленному свободному индексу selection. Известный служебный трафик не требует индекса и сохраняет pagination. Неподдержанное сообщение или исходящее изменение документа, конкурирующая операция, обрыв или потеря наблюдения переводят снимок в `stale`; требуется повторный захват. [Границы live-режима](docs/network-live.md). [Актуальность и восстановление](docs/network-freshness.md). Основной `get_design_context` читает этот снимок автоматически; ручной captureFile не нужен. Остановка, смена файла, перезагрузка вкладки, отключение debugger или переполнение очереди прерывают захват; для повторного запуска подключись к MCP заново. Состояние и причина ошибки показаны отдельно в popup. Закрытие popup оставляет захват работающим. Подробности и ограничения: [сборщик](docs/network-collector.md), [начальный снимок и восстановление](docs/network-initial.md).

## Что получает агент

`get_design_context` по умолчанию использует `source: "network"`. Снимок выбирается из текущей наблюдаемой сессии нужного файла. При отсутствии/устаревании снимка инструмент объясняет необходимость повторного захвата, без автоматического UI-обхода. URL и nodeId не вызывают чтение Layers/Properties; без них читаются только метаданные единственного выделенного узла.

Для продолжения передавай `traversal.continuation` с теми же URL, depth, maxNodes, maxBytes, includeHidden и variablesFile. Поле `traversal` стоит в начале ответа; дочитывай страницы, пока `continuation` не станет `null`. Ответ содержит `adapter`, `snapshot`, `freshness.status/revision` и ограничения. `maxBytes` ограничивает весь JSON (по умолчанию 24000 байт для защиты от усечения клиентом; явно можно увеличить до 150000), `maxNodes` — число узлов на странице. При смене снимка или применении изменения прежнее продолжение отклоняется. `source: "ui"` выбирается явно; `afterNodeId` и `autoTraverse: false` относятся только к нему.

При ненулевом `continuation` полный обход ещё не завершён. Лимит модели или провайдера не делает частичный результат полным: сохраняй последний continuation и явно сообщай об остановке. Журнал `kilo run --format json` можно проверить командой `node scripts/check-kilo-pages.mjs EVENTS.jsonl OUTPUT_PREFIX`: она проверяет всю цепочку, уникальность узлов, свежесть и контрольный повтор первой страницы, учитывая повторную публикацию событий при compaction. Локальный прогон без провайдера: `node scripts/check-live-session.mjs CONFIG_JSON FIGMA_URL OUTPUT_PREFIX`, затем подключить расширение и выполнить «Перезагрузить и захватить». Он проверяет полный сетевой и UI-обход, параллельную работу и отдельный UI-запрос; сверка свойств выполняется `scripts/compare-network-ui.mjs`. Это отдельная проверка MCP, а не доказательство самостоятельного завершения моделью.


| Инструмент | Доступные данные |
| --- | --- |
| `get_connection_status` | Текущее подключение расширения: connected / disconnected / busy, время проверки и пояснение; работает без подключённой Figma |
| `get_selection` | ID, названия и типы выделенных строк, смонтированных в Layers |
| `get_design_context` | Ссылка `url`, `nodeId` или выделение → сетевое дерево, `parentId`, свойства, `layout`, CSS, стили и актуальность; `source: "ui"` включает прежний обход |
| `get_screenshot` | Copy as PNG с уменьшением длинной стороны до 2048 px |
| `export_assets` | PNG через буфер, SVG через Export для указанных смонтированных ID, запись в разрешённую папку |

В явном режиме `source: "ui"` используется DOM-адаптер. В этом режиме по умолчанию `autoTraverse: true`: адаптер раскрывает вложенные группы, прокручивает виртуализированные Layers и по очереди читает Properties. Ссылки на выделение принимаются в `url` у `get_design_context` и `get_screenshot`; файл должен совпадать с подключённым. Сначала ID выбирается через Layers, затем при необходимости пробуется переход по URL. Если Figma не раскрыла путь к скрытому узлу, возвращается явная ошибка; этот запасной сценарий пока не подтверждён на всех типах ссылок. Ссылку на другой файл нужно сначала подключить расширением.

Ответ содержит `nodes[]` со свойствами и `parentId`. Для каждого узла `layout.css`/`cssText` дают распознанные CSS-свойства, `layout.sizing` различает fixed/fill/hug, `layout.source` хранит исходные значения. Токены без числового значения и неизвестные поля идут в `layout.unresolved`; Fill/Hug не подменяются фиксированными пикселями. Отсутствующее поле не означает нулевое значение.

В явном режиме `source: "ui"` обход ограничен глубиной, числом узлов, 18 секундами и 150 000 символами текста. `traversal.nextRequest` даёт готовые аргументы следующего запроса после лимита времени/узлов (без повторного чтения потомков); `traversal.pending` сообщает ветки за пределами глубины, `childrenTruncated` — неполноту обхода. `truncated` остаётся true: даже полный обход не делает DOM полным Figma API. Группы остаются раскрытыми, исходный слой восстанавливается, если пользователь не сменил выделение. Ранее найденные ID адаптер ищет прокруткой. `autoTraverse: false` возвращает прежний быстрый снимок смонтированных строк без инспекции потомков.

В UI-режиме нет гарантии получения абсолютных координат, всех текстовых диапазонов, Auto Layout, значений variables и полного дерева. Возвращаются только сведения, показанные в Properties. Изменение интерфейса Figma может потребовать обновления селекторов. Смена выделения/раскрытие Layers меняют локальное состояние интерфейса, но не документ.

PNG: исходник не более 16 мегапикселей и 12 МиБ, итог не более 3 МиБ; масштаб 0.1–2, длинная сторона до 2048 px. Масштаб относится к PNG в буфере (`scaleBasis: clipboard`), а не к единицам документа Figma. SVG: до 3 МиБ. Ограничения нативного рендеринга Figma применяются до получения результата расширением; для больших экранов выбирай отдельные секции. До 10 ID на пакет, последовательная обработка. Контекст: до 500 видимых узлов, глубина 12, текст секции до 12 000 символов.

## Автоматическая подстановка переменных UI-кита

Сервер читает актуальный `variables.scss` при каждом запросе контекста. Сетевой `get_network_tree` также поддерживает `variablesFile` и настройку из конфига: [контракт, нативные ссылки и ограничения](docs/network-variables.md). Можно передать агенту абсолютный путь к файлу вместе со ссылкой на макет: агент укажет `variablesFile` в `get_design_context`. Подбор значений выполняет код MCP, а не модель. Для постоянного подключения добавь `variablesFile` в существующий `.local/config.json` и перезапусти Kilo:

```json
"variablesFile": "C:/Projects/ui-kit/src/assets/styles/variables.scss"
```

Это поле существующего JSON, не замена всей конфигурации. Windows-пути с пробелами и кириллицей поддерживаются. В JSON обратные слеши экранируются: `C:\\Projects\\ui-kit\\variables.scss`; проще использовать `/`. В чате обычный Windows-путь можно отправить как есть. Файл должен находиться на машине MCP: Windows-путь не предоставляет Mac доступ к Windows-диску. Путь из запроса действует только на этот запрос: повторяй его при сетевом continuation; UI-режим переносит его в `traversal.nextRequest`.

В Properties фактическое значение читается из `data-tooltip` внутри `inspectionPropertyValue → variable-pill-root`; например, Padding Top возвращает `32px`. Имена привязок Figma не участвуют в подборе. Наведение и фиксированная таблица размеров не нужны. Если значение не раскрыто интерфейсом, оно остаётся недоступным.

Правила подстановки UI-кита:

- Отступы, gap, фиксированные width/height и min/max-размеры, позиционные расстояния и line-height → только `--mimir-space-*`. Компонентные размеры и ширины контейнеров не используются.
- Размер шрифта → только `--mimir-size-text-*`; вес → `--mimir-font-weight-text-*`; Inter/Montserrat → `--mimir-font-inter` / `--mimir-font-montserrat`, включая fallback из переменной.
- Радиусы → `--mimir-control-radius*` / `--mimir-control-input-radius`; толщина границы → `--mimir-control-border-width`.
- Цвета → первое точное совпадение в порядке объявления файла. Алиасы `var(--...)` и `--gos-znak-*` исключаются из цветовых кандидатов. HEX и RGB/RGBA сравниваются с учётом прозрачности.
- Тени и z-index остаются исходными. Без точного совпадения значение также сохраняется. Для нецветовых категорий несколько совпадений остаются неоднозначными.

`layout.resolvedValues` сохраняет исходный CSS, `layout.variableMatching` — кандидатов и статусы, включая `unsupported`. Составные padding/margin/gap и радиусы обрабатываются по частям. Line-height в em, процентах или без единиц пересчитывается в px только при известном локальном font-size в px, затем сопоставляется с `space`. Другие единицы без необходимого контекста не пересчитываются. Fill/Hug не превращаются в фиксированную ширину.

Извлечение ограничено именованными полями инспектора. Цветовая сводка Colors не определяет CSS-роль цвета: для неё `layout.colors` содержит исходный `value`, подобранный `cssValue`, кандидатов и статус. Агент применяет эти переменные к свойствам, когда их назначение установлено; MCP не угадывает фон или цвет текста по одной сводке.

Файл до 2 МиБ должен содержать плоские блоки `:root` с CSS custom properties. Поддерживаются простые ссылки `var(--name)`, циклические и повторно объявленные переменные исключаются. Sass не исполняется; импорты, вложенность, темы и вычисления нужно предварительно экспортировать в отдельный плоский файл. Сам файл целиком модели не передаётся. Без `variablesFile` MCP выдаёт обычные числовые CSS-значения.

### Пропуск скрытых слоёв

При чтении контекста скрытые слои и их поддеревья пропускаются: расширение не выбирает их, не читает Properties и не раскрывает детей. Уже раскрытые потомки также исключаются. Пропущенные ветки перечисляются в `traversal.skipped`; они не расходуют `maxNodes` и не требуют продолжения обхода. Если выбранный корень скрыт, возвращается пустой контекст с причиной пропуска.

Признак берётся из inline-цвета строки Layers: `var(--color-text-disabled)` для обычных слоёв и `var(--color-text-component-tertiary)` для компонентов. Это наблюдаемое оформление текущего интерфейса Figma, а не официальный флаг видимости. Неизвестное оформление не исключает слой; свёрнутость сама по себе не означает скрытие. После изменений интерфейса Figma эти признаки могут потребовать обновления.

## Ограничения доступа и ресурсы

Пользователь должен иметь доступ к оригинальному файлу и разрешение владельца на копирование/экспорт. Расширение вызывает только доступные команды интерфейса; отсутствие команды или запрет возвращает ошибку. [Figma описывает доступные viewers свойства и экспорт](https://help.figma.com/hc/en-us/articles/22012921621015-Guide-to-inspecting), а также [ограничения копирования владельцем](https://help.figma.com/hc/en-us/articles/360040045574-Restrict-copying-and-sharing-on-files).

Один процесс MCP-сервера и фоновый процесс расширения в существующем Chrome 125+. Нет отдельного браузера, базы данных, фонового индексирования, телеметрии и платного сервиса в коде моста. Тариф Figma/модели и воспроизводимость всей бесплатной цепочки ещё нужно проверить отдельно; выбранная в Kilo модель получает переданный ей дизайн.

Сервер слушает только `127.0.0.1`, проверяет 256-битный секрет и принимает одно соединение. Таймаут запроса — 30 секунд, ожидание нативного копирования — до 20 секунд. При обрыве ожидание MCP освобождается. Запись ассетов ограничена канонической папкой, имена плоские с UUID, перезаписи нет. Для другого порта измени config.json и поле порта расширения.

## Кэш и очистка

Управляемый сетевой кэш находится в `.cache/figma-network/` внутри клонированной папки этого репозитория, независимо от рабочей папки Kilo. После обновления выполни `npm run build`, перезапусти MCP и перезагрузи расширение. В его окне доступны **«Размер кэша»** и **«Очистить весь кэш»**; требуется подключение к MCP. Очистка удаляет данные всех макетов этой установки, сохраняя настройки, ключ и экспортированные изображения. Во время чтения/записи она сообщает «занято».

Кэш фрейма разделяется по файлу, странице и ID фрейма, затем по сессии и поколению. Общий сетевой снимок хранится отдельно, без копии на каждый фрейм. Удержание при запуске MCP и перед новым захватом оставляет последнее поколение каждой записи до 7 дней и суммарно до 1 ГиБ; это не квота во время записи. Посторонние/непроверенные файлы сохраняются и показываются отдельно. Один MCP-процесс на установку. Подробности: [формат, очистка и ограничения](docs/network-store.md).

Автоматический начальный захват, чтение сохранённых частей и повторное использование индекса выбранной ветки реализованы. Текущий DOM-контекст и ручные исследовательские JSON не становятся кэшированными автоматически. Старые файлы вне нового управляемого кэша не удаляются.

## Проверки

### Эксперимент: дерево из сетевого снимка

Отдельное расширение [Figma Network Probe](experiments/figma-network-probe/README.md) записывает входящий multiplayer-обмен выбранного файла. В версии 0.2.0 шрифты, HTTP-тела, livegraph и исходящие сообщения исключены. После записи скачай JSON и вызови новый MCP-инструмент:

```json
{
  "captureFile": "/absolute/path/figma-probe.json",
  "url": "https://www.figma.com/design/FILE_KEY/File?node-id=1-22975",
  "depth": 12,
  "maxNodes": 200,
  "offset": 0,
  "includeHidden": false
}
```

Имя инструмента — `get_network_tree`. Для появления в Kilo пересобери сервер (`npm ci && npm run build`) и перезапусти его MCP-сессию. Основное расширение для этого инструмента подключать не требуется; файл записи должен находиться на машине MCP-сервера. Для следующей страницы используй `traversal.nextOffset` с теми же параметрами и неизменным captureFile.

Для уже сохранённого основным расширением поколения вместо `captureFile` можно передать `snapshot: {fileKey, sessionId, generation}` из метаданных захвата. Сервер проверит готовность и SHA-256 каждой части; готовый снимок не преобразуется в ручной JSON. Ровно один источник на запрос. Основной `get_design_context` автоматически выбирает наблюдаемый снимок; этот исследовательский инструмент сохраняет явный выбор источника. Лимиты и замеры: [дисковый декодер](docs/network-disk.md).

Для ручного captureFile это **сохранённое начальное состояние**, а не live-данные. Managed snapshot дополнительно поддерживает ограниченные входящие изменения при удерживаемом индексе; см. `freshness` и [границы live-режима](docs/network-live.md). Инструмент проверяет соответствие файла ссылке, наличие JOIN_START/JOIN_END, собирает начальные пакеты CREATED и игнорирует последующие изменения с явным счётчиком. По умолчанию возвращает контекст для вёрстки: свойства, `layout.css`/`cssText`, измерения в `measuredCss`, Fixed/Hug/Fill и координаты. Исходные технические записи доступны через `format: debug`; `copyText` не возвращается. Компоненты выбранной ветки раскрываются адресно с overrides; дочерние ID — устойчивые instance/source paths. Поддержанное подмножество, бюджет зависимостей и явные ошибки описаны в [docs/network-components.md](docs/network-components.md); полного rendered tree для произвольного файла не обещается. Паритет layout проверен на полной контрольной ветке из 103 видимых узлов; методика и ограничения — [docs/network-layout.md](docs/network-layout.md). Текстовые диапазоны, шрифты, paints, обводки, скругления, прозрачность и эффекты доступны в `style`; применимый CSS включён в обычный контекст. [Поддержка и ограничения стилей](docs/network-style.md). Подбор UI-kit поддержан через `variablesFile`; исходный CSS сохраняется в `resolvedValues`. Цвета нативных привязок Figma разрешаются до построения CSS и подбора UI-kit. Имена токенов Figma не передаются в обычном context; подробности доступны только в debug. Неразрешённый цвет обозначается явно. [Нативные переменные](docs/network-native-variables.md). [Переменные и UI-kit](docs/network-variables.md). Изображения и geometry blobs не разрешены. Это не эквивалент REST/Plugin API. Пропуски записи видны в `captureWarnings`, скрытые ветки по умолчанию исключены. Запрос ограничен глубиной, количеством узлов и бюджетом текста; данные макета остаются недоверенным содержимым.

Декодирование выполняется в одном worker с таймаутом 120 секунд. JSON читается по одному событию, узлы и связи записываются в ограниченный временный индекс на диске; полный документ в RAM не строится. Индекс удаляется после запроса, отмены или ошибки. На Node 20 работает без внешнего `zstd` и без Rust; зависимости — `fzstd` и `kiwi-schema`. Полный документ не пересылается модели: только выбранная ветка. Большие и неизвестные варианты протокола завершаются явной ошибкой.

Замер полного декодирования против компактной модели на одном локальном дампе:

```sh
node scripts/measure-network.mjs /absolute/path/figma-probe.json 'https://www.figma.com/design/FILE_KEY/File?node-id=1-22975'
```

Скрипт запускает варианты в отдельных процессах, сообщает время, JS-кучу после GC и пиковый RSS процесса. Это не память Chrome/Figma и не сравнение с реализацией Rust.

```powershell
npm run check
npm test
npm run measure
```

Автотесты проверяют DOM-логику на заглушках, ограничения буфера, привязку к файлу, настоящий stdio MCP/WebSocket, ошибки, отмену и запись ассетов. Они не заменяют запуск распакованного расширения в Chrome. Подробности: [`TEST_REPORT.md`](TEST_REPORT.md).

Для сквозной проверки без вызова модели закрой Kilo и запусти `node scripts/check-real.mjs`. Подключи расширение, выбери небольшой слой, открой Properties и нажми Enter в терминале. Проверка получает контекст, PNG и SVG через настоящий MCP; доказательства сохраняются в `artifacts/browser-*`. Она заменяет буфер обмена. `q` завершает сервер. Этот сценарий проверяет MCP независимо от тарифа модели, но не заменяет приёмку работы агента Kilo.

`npm run measure` использует имитацию браузерного адаптера и измеряет только MCP-процесс. `npm run measure -- --real` требует подключённого расширения и реального выделения; закрой Kilo, чтобы освободить порт. Результаты пишутся в `artifacts/resources-*.json`. Память/CPU расширения и Figma измеряй отдельно в диспетчере задач Chrome. Windows-прогон пока не выполнен.

[Настройка MCP в Kilo CLI](https://kilo.ai/docs/automate/mcp/using-in-kilo-code) · [Временный доступ Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)

### Статус без изменения Kilo CLI

Используется обычный **Kilo CLI в терминале**. Отдельная сборка Kilo, Bun и patch клиента не нужны.

Закрепи **Figma Kilo Browser Bridge** на панели Chrome (меню расширений → значок булавки). Индикатор на значке обновляется автоматически:

- **ON**, зелёный — расширение подключено к MCP;
- **RUN**, синий — выполняется запрос;
- **…**, жёлтый — подключение или ожидание восстановления;
- **OFF**, серый — отключено;
- **!**, красный — подключение отклонено, проверь ключ или другое соединение.

Наведи курсор на значок для пояснения. Нажатие значка открывает статус и поле секрета; ссылка «Информация» открывает README репозитория. Отдельного окна подключения нет. Индикатор отражает связь расширения с MCP, а не готовность документа к экспорту. Изменять Kilo или вызывать модель для проверки не требуется. В панели самого Kilo остаётся штатный статус соединения с MCP-сервером; `get_connection_status` доступен для явного вопроса агенту.

Для раннего измерения сетевого пути используй `npm run measure:network -- --synthetic` или live-режим с явно выбранным PID расширения. Стенд измеряет захват, адаптер снимка, decoder, выборку и освобождение памяти; базовая память вкладки Figma исключена. [Методика, команды и исходный live-замер](docs/network-measurements.md). Наблюдаемый пик не является приёмкой лимита 500 МБ.
